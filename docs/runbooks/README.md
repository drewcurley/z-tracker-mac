# Runbooks — z-tracker-mac

One file per operational scenario. There is no on-call/fleet to page for a
local desktop app — "operational" here means "what the developer (or a user
filing a bug) does when something goes wrong," not incident response for a
service.

- [corrupted-or-unreadable-save-file.md](./corrupted-or-unreadable-save-file.md)

## Update-this-doc-when

Add a runbook whenever a support scenario recurs enough to be worth writing
down (e.g., "app won't launch after an OS update," once that's a real thing
that's happened).
