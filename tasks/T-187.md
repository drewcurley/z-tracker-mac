# T-187 — App theme chooser

Replaces the reference's never-implemented "Dungeon 'sunglasses'" toggle (one of ~14
dead settings toggles found in the settings audit) with a real app **Theme** picker.

## What shipped
- `AppTheme` enum (`dark` default / `light` / `system`) in TrackerCore, persisted under
  its own settings key.
- `dungeonSunglasses` removed (field + init + persistence + settings toggle + test).
- **Theme** picker in Settings → Other (startup + mid-game window).
- `AppThemeController.apply` sets `NSApp.appearance` (darkAqua / aqua / nil-for-system),
  which re-themes every window (tracker, Settings, Timeline, Broadcast) live; applied on
  launch and on change via ContentView. Default dark now makes the chrome *consistently*
  dark rather than quietly following the OS.

## Tests
`TrackerOptionsTests`: default is `.dark`; theme persists across launches. 721 tests pass.

## Known limitation → follow-up (T-188)
The picker/mechanism works, but **Light mode only re-themes the standard chrome**; the
game board (overworld art, sprites, and the many hardcoded dark box/panel fills) stays
dark, so Light reads as "dark board on light frame" with accessibility/contrast issues.
Making Light genuinely good is a separate design-system pass — tracked as T-188.
