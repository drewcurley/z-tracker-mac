# T-098 — Timeline phase 1

## Description
The Timeline (one of the four big missing pillars): a minute-axis retrospective of
when each item / triforce / take-any heart was acquired, with the finish time.
Phase 1 = the item strip (this task); the overworld-progress line graph is phase 2,
and pop-out-into-a-window is a separate follow-up.

- `TimelineModel` (TrackerCore, `@Observable`) on `TrackerModel.timeline`: stamps
  each event's first-acquisition **elapsed run seconds**, drops events that are
  un-marked (so re-acquiring re-stamps), and captures the finish snapshot (time +
  OW-remaining) when Zelda is rescued. Fed once a second from the poll loop
  (`recordTimeline`, gated on `timer.hasStarted`). Session-only until Save/Load.
- `TimelineEvents.current(...)` derives the acquired set from live state.
- `GameTimelineView` (ZTrackerMac): a horizontal minute axis with gridlines/labels,
  each event's icon at its acquisition minute (stacked within a minute), hover
  shows the exact `m:ss` split, and a finish marker. Icons from `ItemIconAtlas`
  (triforce uses an SF Symbol). (Named `Game…` to avoid SwiftUI's `TimelineView`.)
- Inline, collapsible section (shown by default) below the dungeon band.

## Acceptance criteria
- [x] Acquiring an item stamps it at the current run time; hover shows the split.
- [x] Un-marking drops the stamp; re-marking re-stamps (matches reminder re-fire).
- [x] Finish (Zelda) freezes final time + OW-remaining.
- [x] Inline + collapsible; fed from the 1 Hz poll once the run has started.
- [x] Model unit-tested; build clean; launches without crash.
