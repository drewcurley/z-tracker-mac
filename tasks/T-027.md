# T-027 — Always-empty tile polish

## Description
Two pieces of user feedback on T-026's always-empty tiles:

1. **Drop the X.** A simply darkened tile already reads as "nothing here"; the
   stamped X was visual noise that added nothing. Match the darkening to the
   existing user `.dontCare` treatment (terrain + 0.62 black) so the two look
   identical, as the reference intends (both are DARK_X).
2. **Show fairy icons.** The reference draws a fairy on three always-empty
   screens — the fixed fairy-fountain spots (`WPFUI.fs:488-490`): `(9,3)` and
   `(3,4)` in every quest, plus `(11,0)` in second quest only. These were
   deferred in T-026; restore them.

Fairy sprite: `icons8x16.png` (8×16, black→transparent) — the whole image is
the fairy (`Graphics.fs:684-693`), newly vendored.

## Acceptance criteria
- [x] Always-empty tiles render as darkened terrain only (no X), matching the
      `.dontCare` darkening (0.62 black). On-device verified.
- [x] Fairy icon drawn on `(9,3)`, `(3,4)` (all quests) and `(11,0)`
      (second quest only), centered on the darkened tile. On-device verified
      the two first-quest spots.
- [x] `icons8x16.png` vendored (+ NOTICE attribution); loads via the existing
      black-key `AtlasLoader` path (no alpha channel, so masking works).
- [x] Tests: pure `OverworldFairySpots.isFairySpot(column:row:quest:)` matches
      the three spots + second-quest-only; a cross-check that each spot is
      always-empty for its quest; sprite loads at 8×16.

## Out of scope
