# T-035.1 — Dynamic status fields

## Description
The reference's "65 OW spots left" and "26 gettable" readouts
(`OverworldItemGridUI.fs` / `WPFUI.fs` spot-summary area). Both are already
computed in `MapStateSummary`:

- **OW spots left** = `owSpotsRemain` (total unmarked overworld spots).
- **gettable** = `owGettableLocations.trueCount` — the unmarked spots the
  player can currently *uncover* given their items, which the compute already
  gates capability-by-capability, per quest
  (`MapStateSummary.swift:167-184`: whistle/bracelet/ladder/raft/bomb/burn vs
  `haveRecorder`/`havePowerBracelet`/`haveLadder`/`haveRaft`/`hasBombs`/
  `candleLevel`). So the raft-opens-2 / recorder-1-in-1Q-10-in-2Q behavior falls
  out of the existing per-quest capability masks — no new logic needed.

This task just *displays* them (live) in the item-grid chrome next to Max
Hearts.

## Acceptance criteria
- [x] "N OW spots left" + "N gettable" render in the chrome, reading
      `mapState.owSpotsRemain` / `owGettableLocations.trueCount`.
- [x] They update live as marks/items change (they're derived from the
      `@Observable` model each body eval).
- [x] Tests: assert the displayed values track a couple of representative
      model scenarios (the underlying compute is already tested; this pins the
      "gettable = trueCount" / "spots = owSpotsRemain" wiring).

## Out of scope
- The overlay toggles (T-035.2/.3) and the gettable *highlight* checkbox (the
  GYR highlight already exists via `options.highlightNearby`).
