# T-244 — Overworld hover isolation

## Problem (audit, High)
Each overworld tile's closure read the hover route (`routeHighlight`, the map's `@State`) for the
GYR tint and the keyboard cursor (`focus`) for its ring — and route drawing / nearby highlighting are
on by default. So every tile crossing re-ran the whole 128-tile grid body (≈10 overlays, 3 popovers
and menu closures per tile), and the broadcast mirror did it again: an estimated 30–50 ms per crossing.
The routing graph was also rebuilt on every mouse-move event, before the "same vertex" check.

## Fix
- Hover state moved into `OverworldHoverState` (`@Observable`; only `route` observed). The map body
  only *writes* it from `handleHover`.
- New `OverworldHoverLayer` above the grid draws the GYR tint, route lines and cursor ring — the only
  view that observes hover/cursor state. Per-tile GYR and cursor overlays removed.
- Routing graph cached by (ladder, raft, any-roads, screen-scrolls).

## Visual note
The GYR tint and cursor ring now draw above each tile's own overlays (marker/enemy glyphs) instead of
beneath them — a translucent tint, so it reads the same; worth a glance during QA.
