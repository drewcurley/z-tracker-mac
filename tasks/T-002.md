# T-002 — Initial Xcode/SwiftPM project scaffold

## Description
The first real code task. Creates the buildable skeleton `docs/onboarding.md`,
`docs/testing.md`, and `.github/workflows/checks.yml` already assume exists:
an Xcode project (or SwiftPM package driving an app target) targeting macOS,
Apple Silicon, with an empty `TrackerModel` and a placeholder SwiftUI window,
plus a unit test target that actually runs. This task is also where several
docs' explicit "UNKNOWN — needs human confirmation" items must be resolved,
not deferred further:
- Minimum macOS deployment target (`stack.md`).
- Sprite-rendering approach: SwiftUI-only vs. AppKit/Core Graphics interop
  (`stack.md`).
- macOS-appropriate save-file storage location (`data-model.md` § 1).

## Acceptance criteria
- [x] Project builds and runs a minimal window on Apple Silicon (SwiftPM
      package, not an `.xcodeproj` — `swift run ZTrackerMac`, verified to
      launch and stay running).
- [x] `swift build` / `swift test` succeed in CI — `continue-on-error: true`
      removed from the `build-and-test` job in `.github/workflows/checks.yml`.
- [x] At least one real automated test exists and passes — 5 tests, via
      **Swift Testing** rather than XCTest (a resolved decision, not a miss —
      see `docs/decisions/0002-scaffold-decisions.md`).
- [x] `stack.md` and `data-model.md` updated to replace the resolved UNKNOWNs
      (deployment target, sprite-rendering approach, save location) with the
      actual decisions, recorded in ADR 0002.
- [x] `onboarding.md` updated with the real, verified build/run/test commands.

## Out of scope
- Any actual tracker feature from `domain.md` — this is scaffold only.

## Risks / dependencies
- Depends on T-001 (this repo's docs bootstrap) being complete — it is.
