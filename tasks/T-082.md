# T-082 — Blockers: need/might-need + applies-to

## Description
Two reference blocker features the user asked to restore now that they understand
the workflow:

1. **Need vs might-need.** The kind picker now shows both the definite ("Need")
   and uncertain ("Might need") kinds — the reference's full `DungeonBlocker.All`
   grid — in two labeled sections; the maybe kinds carry the green→red gradient
   edge that matches the box border.
2. **Applies to.** Right-click a blocker box opens the "Applies to…" panel
   (reference `doPanel`, `UIComponents.fs:868-902`): All / None + a checkbox per
   dungeon cell the blocker sits in front of. The flags surface as tiny blocker
   **chips** on the dungeon card's triforce (while unobtained) and item boxes
   (`Views.fs:134,306`); a chip turns **lime** once the player has the item that
   unblocks it. Left-click still sets the kind; right-click now sets applies-to
   (it used to duplicate the kind picker).

This tracker's dungeon cards have no separate map/compass cell, so those two
reference applies-to elements are omitted from the panel (they'd chip nowhere);
the model still stores all six flags for save-file parity.
