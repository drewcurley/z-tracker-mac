# T-067 — Accessibility catch-up pass

## Description
The overworld tiles, item grid, and reminders already had VoiceOver support; the
rest of the interactive views did not. This brings them up to a documented
baseline (`docs/ux.md` § Accessibility baseline — decided as part of this task).
The app is icon/gesture-driven, so a plain `.onTapGesture` view is invisible to
VoiceOver; each such control needs an explicit accessibility element.

Covered (custom `.onTapGesture` controls + icon-only / empty-label standard
controls):
- **`HintLabel`** → element: label + value (current hint) + button trait + action.
- **`DungeonNumberLabel`** → element + label + value.
- **`GhostBoxView`** → element + label + action.
- **`BoxView`** → element + label + state value + primary + "Set item" actions.
- **`BoxItemPicker`** icon items → per-item name (new `ItemIconAtlas.Icon.displayName`
  / `itemName(forItemIndex:)`) + current/unavailable value + actions.
- **`DungeonNumberPicker`** color swatches (icon-only) → color label + selected.
- **Triforce pip** (icon-only `Button`) → label + value.
- **SettingsPanel** reminder `Toggle("", …)` (empty labels) → "Voice/Visual
  reminder: X"; volume slider → label.

Not needed (already accessible): text-labeled buttons in `StartupView`,
`TimerView`, `TopSectionControls`, and the `Button`-based number/zone grids.

## Acceptance criteria
- [x] Every custom `.onTapGesture` interactive control is an accessibility
      element (label + value-where-stateful + `.isButton` + action, plus a named
      action for secondary gestures).
- [x] Icon-only / empty-label standard controls carry an explicit label.
- [x] The convention is written in `docs/ux.md` for all future views.
- [x] Build clean (debug + release); full suite passes (340).

## Verification note (honest)
VoiceOver *behavior* was not driven on-device. The only scripting bridge
available, `System Events`, **cannot traverse the main tracker's SwiftUI tree**
(`entire contents` errors: "AppleEvent handler failed"), and turning on VoiceOver
would disrupt the user's machine. The changes are the standard SwiftUI
accessibility modifiers, verified by build + full suite + code review; a manual
VoiceOver pass is warranted before any public release. (This also settled the
automation question: `System Events` is not viable for the main tracker; AXPress
works only on simple screens — see the branch discussion. XCUITest, deferred to
the `.app` distribution milestone, is the real automation path.)

## Out of scope
- Reduce-Motion honoring (in the convention; applies when animations land).
- Automation infrastructure / XCUITest.
