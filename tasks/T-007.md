# T-007 — Overworld map real sprite rendering

## Description
`T-006` deliberately used placeholder colored rectangles instead of the
reference app's real sprite icons. This task replaces them with the real
assets (`Z1R_Tracker/Z1R_WPF/icons/s_icon_overworld_strip39.png`, MIT-licensed
per ADR 0001 — reuse with attribution is legally clean), per the sprite
rendering approach already decided in ADR 0002 (`Canvas` + `CGImage`
cropping, no AppKit interop for v1).

## Acceptance criteria
- [ ] Icon strip asset copied into the SwiftPM package as a bundled resource
      (`Bundle.module`), with attribution recorded per ADR 0001.
- [ ] The index-to-tile-mark mapping is extracted from the reference
      source (not guessed) — likely from `Graphics.fs` or `TrackerModel.fs`
      wherever the strip is indexed by tile kind.
- [ ] `TileView` renders the correct cropped icon per `OverworldTileMark`,
      with nearest-neighbor scaling (no blur) at arbitrary window sizes —
      resolving the "integer-scale snapping" open problem from ADR 0003.
- [ ] Visual comparison against a reference-app screenshot or the icon
      strip directly to confirm icons are correctly identified, not just
      "some icon renders."

## Out of scope
- The overworld map's background/terrain art (separate, more complex
  per-quest bitmap system in the reference app — needs its own investigation).
- GYR highlighting, routing lines, magnifier, take-any pie menu — still
  tracked generally under `docs/domain.md` § 4.5, no dedicated task yet.

## Risks / dependencies
- Depends on `T-006` — complete.
