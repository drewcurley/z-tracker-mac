# T-007 — Overworld map real sprite rendering

## Description
`T-006` deliberately used placeholder colored rectangles instead of the
reference app's real sprite icons. This task replaces them with the real
assets, and along the way resolved the tile-mark count discrepancy `T-006`
had flagged as open: reading `MapSquareChoiceDomainHelper`
(`TrackerModel.fs:310-354`) directly — the reference app's own authoritative
tile-index enumeration — confirmed exactly 36 indices, matching this
project's `OverworldTileMark` exactly. `domain.md`'s "38" was the actual
error, now corrected.

## Acceptance criteria
- [x] Icon strip asset (`s_icon_overworld_strip39.png`) copied into the
      SwiftPM package as a bundled resource (`Package.swift` `resources:`),
      with attribution recorded in `/NOTICE.md` (MIT license, Brian McNamara).
- [x] The index-to-tile-mark mapping is extracted from the reference source
      (`MapSquareChoiceDomainHelper`, not guessed) — implemented as
      `OverworldTileMark.iconStripIndex`, exhaustively tested (all 36
      indices 0...35 present, no duplicates).
- [x] `TileView` renders the correct cropped icon per `OverworldTileMark`
      via `OverworldIconAtlas`, with nearest-neighbor scaling (`.interpolation(.none)`).
      Used `Image(decorative:)` rather than a literal `Canvas` (ADR 0002's
      exact wording) — equivalent output for a single static icon; documented
      as an intentional implementation-level deviation, not silently diverged.
- [x] Verified visually: launched the app, marked several tiles, confirmed
      the real reference-app icon (crisp, correctly cropped) renders in place
      of the placeholder color.

## Out of scope
- The overworld map's background/terrain art (separate, more complex
  per-quest bitmap system in the reference app — still needs its own
  investigation, `Graphics.fs` `overworldMapBMPs`).
- GYR highlighting, routing lines, magnifier, take-any pie menu — still
  tracked generally under `docs/domain.md` § 4.5, no dedicated task yet.
- Integer-scale snapping at arbitrary window sizes (ADR 0003's open
  implementation problem) — `.interpolation(.none)` gives crisp pixels at
  any scale SwiftUI renders at, but exact integer-multiple snapping for
  maximum crispness was not implemented or verified.
