# T-035.7 — Recorder-destination tracker

## Description
Tracks where the recorder (whistle) warps you. Two parts:
- **Availability logic** (`RecorderDestinations.compute`, ported from
  `TrackerModel.fs:1606-1619`): empty unless the player has the recorder; for
  each dungeon level 1–8, included when `hasTriforce != toUnbeatenDungeons`;
  emits the discovered map location (if `toNewDungeons`, requires the dungeon
  located) or the fixed vanilla-1Q screen. Two checkboxes drive it.
- **A below-map stepper** — the single place to see the current destination.
  Two arrows step the whistle count through the ordered available list; the
  current one is named (dungeon label + coord + n/total) and marked with a lone
  diamond on the map.

**Design corrected mid-build (user feedback):** v1 put a diamond on *every*
available destination (forcing a map scan). The reference + user want a single
below-map widget as the one place to look, with at most one diamond on the
*current* destination. Destinations key off **triforce held**, not full
completion.

## Acceptance criteria
- [x] Two checkboxes ("to new dungeons", "to unbeaten dungeons") behind a
      settings button on the bar.
- [x] Below-map stepper shows the current destination (label, coord, position).
- [x] ◄ ► step through the ordered available destinations (wrapping).
- [x] Exactly one diamond on the current destination; none when empty.
- [x] Keyed off `playerHasTriforce`, not `isComplete`; empty without recorder.
