# T-006 — Overworld map (core data model + basic grid)

## Description
First slice of the overworld map (`docs/domain.md` § 4.5) — the largest
remaining unbuilt piece of the main tracker view. Given the reference app's
map rendering turns out to involve real bitmap-cropping/caching logic
(`Graphics.fs` — a 16×11px base tile rendered at 3x scale, `OMTW`/`OMTH`
constants now resolved, per-quest cached tile bitmaps), this task
deliberately scopes to the **data model and interaction**, not
pixel-perfect rendering, matching the incremental pattern that worked well
for the startup screen (T-003→T-005).

## Acceptance criteria
- [x] `OverworldTileMark` models every confirmed tile-mark kind from
      `domain.md` § 4.5. **Note:** a real count discrepancy was found and
      documented, not silently resolved — this enum has 36 marked states,
      `domain.md` says "38," and the reference app's own icon strip has 39
      images. Flagged in the type's doc comment and `domain.md` § 4.5/§ 6.
- [x] A 16×8 grid state type (`OverworldGrid`) in `TrackerCore` holds one
      mark per tile, defaulting to unmarked.
- [x] Real tests cover the model — 12 new test functions across
      `OverworldTileMarkTests`/`OverworldGridTests` (dimensions, defaults,
      scoped mutation, Codable round-trip, all associated-value cases).
- [x] A basic SwiftUI grid view (`OverworldMapView`) renders the 16×8 grid
      and supports the core confirmed gesture — verified two ways: unit
      tests on the model, and an actual click through the accessibility API
      on the running app, confirmed by both the tile's updated accessibility
      value and a screenshot showing the visual change.
- [x] Responsive per ADR 0003 — `GeometryReader`-driven tile sizing, no fixed
      pixel dimensions.
- [x] Wired into the main tracker view via `TrackerModel.overworldGrid`.

**Found during verification, fixed in the same task (not deferred):** the
custom Rectangle+`onTapGesture` tiles had **no accessibility representation
at all** — confirmed by inspecting the accessibility tree, not assumed. Added
proper `accessibilityElement`/`accessibilityLabel`/`accessibilityAction` to
each tile, resolving both the testability gap and a real, `ux.md`-flagged
product requirement ("accessibility... should not be deferred past the
first UI-bearing task" — this is the first view with fully custom
interactive elements, not standard controls).

## Out of scope (tracked as follow-ups)
- Real sprite-based rendering using the reference app's actual icon assets
  — tracked as `T-007`.
- The actual overworld map background art (terrain) — the reference app's
  own generation of this is non-trivial (per-quest bitmap caching in
  `Graphics.fs`) and deserves dedicated investigation, not a rushed guess.
- GYR reachability highlighting, routing lines, the "Link" routing feature,
  the take-any pie-menu accelerator, hover magnifier, and the exact popup UI
  shape (versus a context-menu stand-in).
- Overworld quest selection wiring (73/80/93/128 spot counts per quest type)
  and any actual gameplay-state derivation.
- Resolving the 36-vs-38-vs-39 tile-mark count discrepancy.

## Risks / dependencies
- Depends on `T-005` (settings panel) — complete, no blocking relationship
  otherwise.
- This is a large feature; expect several more follow-up tasks before the
  overworld map is feature-complete. Scoped deliberately small here.
