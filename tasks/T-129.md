# T-129 — Zoom fixes

Three fixes/refinements to the dungeon-map zoom (T-127/T-128), all user-QA'd.

## 1. Runaway height at >100%
`ScaledFootprint` measured the content height and set `frame(height: natural × scale)`;
at scale > 1 the taller frame was proposed back into the content, which re-measured
larger each pass — a runaway (map/Notes grew to ~10,000px). Pinned the content to its
intrinsic height (`fixedSize(horizontal: false, vertical: true)`) so the outer frame
can't feed a bigger height back in. (Only surfaced once 120% became reachable in T-128.)

## 2. Zoom reset on reflow
The band's `ViewThatFits` recreates whichever branch it shows, wiping the map view's
`@State` zoom on every row↔column swap. Moved `mapScale` up to `DungeonBandView`
(stable across the swap) and passed it as a binding, so the zoom persists.

## 3. Larger zoom control
The −/+ magnifiers now span the info-strip width (72pt) with the current % above (tap
to reset to 100%), matching the sidebar icons instead of a cramped corner pill.

## Acceptance criteria
- [x] 120% no longer runs away.
- [x] Zoom persists when the band reflows.
- [x] Zoom buttons are larger and align with the info strip.
- [x] Reflow still stacks correctly when narrow (kept `ViewThatFits`).
- [x] Build + full suite clean.
