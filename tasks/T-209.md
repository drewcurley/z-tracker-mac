# T-209 — Timeline fits the whole run

## Problem
The timeline drew at a fixed **26 px/min** inside a horizontal `ScrollView`. A long game
(a real 2h16m run) was ~3,600 px wide, so only the first ~40 minutes were visible; the rest —
and most of the item icons — sat off-screen to the right, unscrolled. It read as "broken /
empty" even though the data was intact (the autosave held all 42 events out to 132 min). A
brand-new game looked fine because a few minutes fit the pane.

## Fix (`GameTimelineView`)
- **Fit-to-width:** `pxPerMinute` scales so the whole run fits the measured pane width, capped
  at 26 (short runs stay full-scale, left-aligned — unchanged) and floored at 6 (only an
  extreme run grows past the pane and scrolls). Width measured via a background `GeometryReader`
  on the outer frame (no layout feedback loop); rescales live as the window resizes.
- **Adaptive axis:** gridline/label interval grows 1 → 2 → 3 → 5 → 10 … min (nearest "nice"
  step keeping minor lines ≥14px and labels ≥48px apart), so a 135-min run reads `0m…130m`
  instead of stopping at 35m. Major/labeled lines are drawn in a second pass so they align with
  labels regardless of the minor/major ratio.
- **Proximity icon stacking:** icons stack vertically by pixel-closeness (an icon-width of
  run-time at the current scale) instead of a fixed per-minute bucket, so a compressed long run
  doesn't smear pickups on top of each other.

## Acceptance criteria
- [x] A ~135-min run shows its entire span in the pane (verified with a 42-event fixture).
- [x] Axis labels scale (10-min steps at that length) and stay readable.
- [x] Short runs are unchanged (≤26 px/min, left-aligned).
- [x] Rescales live on window resize.

## Notes
- Verified against a reconstructed long-run save (`ztracker-longrun-test.json`) since the
  original 2h16m run's autosave was overwritten by a later session and the machine has no root
  to mount the Time Machine local snapshot that still held it.
