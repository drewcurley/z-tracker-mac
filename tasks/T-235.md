# T-235 — Custom-map spot counting

## Problem
On an imported **custom map** the tracker still reasoned with the **vanilla quest terrain masks**
(which screens can hide a cave/dungeon, bombable/ladderable/…). On a custom map "anything can be
anywhere," so those masks are meaningless. Symptoms:
- **"OW spots left"** counted every unmarked screen (128 − marked), not the quest's real spot total.
- The INFO **"available overworld spots"** highlight lit up the vanilla-quest-programmed spots.
- `owGettableLocations` (and the whistle/bracelet counts) were mask-derived and meaningless.

## Fix (custom maps only — vanilla behavior unchanged)
- **Spots left = quest spot total − screens marked as a real spot**, where the total is a property of
  the chosen quest: **73** (first / mixed-first), **80** (second / mixed-second) — added as
  `OverworldQuest.overworldSpotTotal`. A real spot is any mark that isn't `.unmarked` or the
  "confirmed-empty" `.dontCare` (DarkX).
- **New "undiscovered" count** = overworld screens still under fog (`OverworldGrid.customMapFogCount`),
  surfaced as a new readout line (shown only on custom maps, replacing the hidden "gettable").
- **Invariant:** every remaining spot is necessarily still fogged (marking reveals), so spots-left is
  clamped to never exceed undiscovered.
- **Mask leak removed:** the whistle/bracelet/gettable computation is skipped on custom maps.
- **INFO highlight disabled on custom maps:** both open-caves modes (green quest-mask + orange
  mask-based gettable) are turned off in custom-map mode, matching the already-disabled hover-route
  highlight. The mark-based money-secret highlight still works.

The Spot Summary's secret / unique / non-unique tallies were already quest-driven (1Q 3/7/4 vs 2Q
1/7/6, etc.) and thus already correct for custom maps — unchanged.

## Acceptance criteria
- [x] Custom map, first quest: "OW spots left" starts at 73 and drops by 1 per real spot marked;
      `.dontCare` reveals but doesn't reduce it.
- [x] "Undiscovered" shows the fogged-screen count and never rises above nothing; spots-left ≤ undiscovered always.
- [x] Second / mixed-second custom maps use an 80 total; first / mixed-first use 73.
- [x] The INFO open-caves/all-gettable highlight draws nothing on a custom map.
- [x] Vanilla maps are unchanged (spots-left + gettable as before; undiscovered = 0, not shown).

## Notes
- 73/80 totals per the project owner's quest ruleset; kept in one place (`overworldSpotTotal`) so
  they're trivially adjustable. Mixed quests have 93 potential screen positions but the same *used*
  totals (73/80), so the constant keys off `isFirstQuestOverworld`.
