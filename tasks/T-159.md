# T-159 — Dungeon blockers voice

## Description
The `.blockers` region already had a keyboard cursor, hover, and dims, but voice fell
through to "region not supported yet". This adds the blocker vocabulary + apply, exactly
mirroring the dungeon-room voice pattern (act at the cursor cell): hover a blocker slot
(or cycle the cursor there), then speak the blocker.

- New `VoiceCategory.blockers` (editor-visible) + `VoiceConfig.Scope.blocker`. Catalog
  ids equal `DungeonBlocker.asHotKeyName`, so `blockerAction` maps a match straight back
  via `fromHotKeyName`. "maybe / might need X" beats "X" by longest-phrase-wins.
- `parse()` routes blocker words to `actionAtCursor` (via a `.blocker` match alongside
  `.region`) — blocker-only words ("ladder", "recorder", "combat") aren't region words,
  so they needed routing; execution applies them only in the blockers region.
- `VoiceController`: `.blockers` apply sets the cursor's dungeon+slot; `.blockers` clear
  empties the slot (a slot holds one blocker).

## Scope boundary
Reached by mouse-hover-then-speak (same as dungeon rooms). A *spoken* way to enter the
blockers region hands-free is the deferred region-nav / auto-route work (task_ca026250),
not this task.

## Acceptance criteria
- [x] "ladder" → Need ladder; "maybe ladder" → Might need ladder; "nothing" → clear.
- [x] Every catalog blocker phrase resolves to the kind whose hotkey-name matches its id.
- [x] Bare blocker-only words parse to `actionAtCursor` (route into the region).
- [x] Apply/clear set and empty the cursor's dungeon+slot.
- [x] 621 tests.
