# T-229 — Universal UI zoom

A complementary, opt-in **application-level zoom** that scales the entire tracker uniformly, so it
fits a small screen (a single 1080p monitor shared with the game) — chiefly to reduce overall
**height**, which the responsive breakpoints ([T-228](./T-228.md)) can't do. Ships (with T-228) as
**v1.2.7**.

## Behavior
- **"Tracker zoom" setting** (welcome screen + in-app settings): a picker at **100 / 90 / 80 / 70 /
  60%**. Persisted as a display pref (`@AppStorage "ui.zoom"`).
- **Browser-style, not a naive shrink.** Zooming out lays the content out at the *enlarged logical
  width* (viewport ÷ zoom), then scales it back down to fill the real window — so zooming out frees
  **horizontal** room too: panels stay expanded and buttons full-size longer, and the responsive
  breakpoints compose with the zoom instead of fighting it.
- The broadcast/mirror window ignores zoom (always renders full-size for streaming).

## Acceptance criteria
- [x] Given zoom = 80% on a ~975-wide window, the layout behaves like ~1219 wide (panels expanded)
      and the whole tracker renders at 80% — reclaiming vertical *and* horizontal room.
- [x] Given the window is narrowed then widened while zoomed, the canvas re-fills the window (no
      stuck crop).
- [x] At zoom = 100% the layout is byte-for-byte the pre-feature behavior (feature fully inert).
- [x] The mirror window is unaffected.

## Implementation
- Reuses the existing `ScaledFootprint` modifier (scale **and** collapse the layout footprint),
  applied to the whole tracker content in `MainTrackerPlaceholderView`.
- `effectiveWidth = contentWidth / zoom` feeds the T-228 breakpoints; `zoomLayoutWidth` forces the
  content's layout width to that enlarged value (guarded to `nil` before the first measurement to
  avoid a giant-frame flash).
- The ScrollView is forced to fill the window (`maxWidth/maxHeight: .infinity`) so the viewport
  reader tracks true window width even though the zoomed content has a fixed pixel width — otherwise
  the vertical ScrollView shrinks to the content and the canvas stays cropped after a widen.
- `effectiveZoom` is `1.0` on the mirror (`isMirror`).

## Out of scope
- Per-view reflow inside the zoom (the responsive breakpoints handle horizontal narrowing).
- A keyboard shortcut / pinch-zoom — the setting picker is the v1 control.

## Notes
- Trade-off (surfaced to the user before building): uniform scaling means text and pixel-art soften
  slightly at non-round scales (90/70%); 100/80/60% stay crispest. No reflow within the zoom itself.
