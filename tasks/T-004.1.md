# T-004.1 — Reminder settings persistence + header alignment

## Description
The startup screen's **Reminders** section was already wired at runtime
(`ReminderController.handle` gates voice/visual output per category and applies
the volume; the audio engine honors it), but nothing **persisted** — every
launch reset the toggles, volume, and preferred voice to defaults. Added
`UserDefaults`-backed persistence for the reminders settings, and fixed a
column-alignment bug in the same section.

- **Persistence (TrackerCore):** `TrackerOptions` now persists `reminderVolume`,
  the per-category `voiceReminders` / `visualReminders`, and
  `preferredVoiceIdentifier`. `didSet` observers on those four properties save
  automatically, so every mutation (a toggle, the volume slider, "Disable all",
  the voice picker) is covered. `enableReminderPersistence(store:)` loads saved
  values over the current defaults at launch (unknown/missing categories keep
  their default — forward-compatible); `withReminderPersistence()` is the app's
  factory. Persistence is opt-in, so plain `TrackerOptions()` (tests/previews)
  never touches `UserDefaults`.
- **App wiring:** `ZTrackerMacApp` builds `options` via
  `TrackerOptions.withReminderPersistence()`. Reset App keeps `options`, so
  settings survive an in-app reset too.
- **Header alignment fix:** the Reminders grid's header row had a leading 1pt
  spacer that pushed "Voice"/"Visual" one column right (over the Visual box and
  the category name). Removed it and centered each header over its checkbox
  column.

Only the Reminders section persists for now (other settings remain
session-only), matching the scope of this request.
