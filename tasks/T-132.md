# T-132 — Global hotkey dispatch (Part B, phase 1)

## Description
Makes **Global** hotkeys actually fire — the first slice of runtime dispatch (Part B),
proving the pipeline before the cursor subsystem and hover-region contexts.

`GlobalHotkeyDispatcher` installs a local key-down monitor while the main tracker view
is on screen. It only acts for the **main window** (`"Z-Tracker"`) and never while a
text field is being edited (so Notes / the editor filter type normally), resolves the
pressed chord against the Global bindings (`HotkeyConfig.selectorID(boundTo:in:)`), and
performs the action:

- the 9 item toggles → `playerProgress.has*` flags,
- `Global_StartTimer` → `timer.start()`,
- `Global_GroundhogReset` → `resetForGroundhogOrRouters()` (no dialog).

Cursor / dungeon-tab / click / scroll Global selectors are recognized but no-op until
their phases land (they pass through so as not to swallow keys).

Chord-from-`NSEvent` was extracted to a shared `HotkeyChord(nsEvent:)` used by both the
editor's capture and the dispatcher.

## Acceptance criteria
- [x] A bound Global key fires its action from anywhere in the main window.
- [x] Keys don't fire while editing text, or in other windows.
- [x] Reverse lookup unit-tested; user-QA'd (magical-sword toggle on/off via `m`).
- [x] Build + full suite clean.
