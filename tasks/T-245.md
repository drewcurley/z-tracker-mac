# T-245 — Idle CPU while streaming

## Problems (audit, High/Medium)
- **Atlas crops per call:** `OverworldBackgroundAtlas.tile` and the icon atlases returned a fresh
  `CGImage` from `cropping(to:)` on every call, so every tile looked changed to SwiftUI and all 128
  tile bodies re-ran (and likely re-uploaded textures) on any map update.
- **Per-tile 24 fps clocks:** `PulsingHighlight` (on by default with "Animate tile changes") ran its own
  `TimelineView` per highlighted tile — dozens of clocks re-running bodies forever while an overlay
  was locked, doubled by the mirror.
- **Second once-a-second re-layout:** the 1 Hz poll wrote `TimelineModel.latestSeconds` every tick, so
  the timeline (and the tracker's layout) updated every second though its layout changes per minute;
  `acquiredLocation` was reassigned every tick too.
- **Panel cursor rings:** the Items / Blockers / dungeon-item rings were `@ViewBuilder` helpers reading
  `focus` in the parent, so every cursor move re-rendered the whole panel.

## Fix
- All five atlases crop once into static arrays (`[quest][128]` tiles; icon arrays).
- `PulsingHighlight` is a `PhaseAnimator` between dim/bright phases (body runs ~2×/breath, animation
  scoped to the highlight — the original `withAnimation(.repeatForever)` leak can't recur).
- `latestSeconds` is `@ObservationIgnored` (exact, persisted); views read `displaySeconds` (10 s steps,
  sub-pixel at the timeline's fit-to-pane scale); `acquiredLocation` assigned only on change.
- `FocusCursorRing` view: the ring observes `focus`, not the panel.
