# T-095 — Reminder behavior fixes

## Description
Two user-reported reminder bugs:

1. **Recorder (and power bracelet):** the every-5-min "There are N recorder spots"
   reminder was unwanted *and* wrong (the count kept reading 1). Replaced it with a
   one-shot **"Don't forget you have the recorder"** (and power bracelet) nudge —
   the user wanted a plain "you have it" reminder, not the perpetual count. Removed
   the recorder/PB spot-count reminders, their trackers, params, and the
   `recorderSpots`/`powerBraceletSpots` announcements.

2. **Unmark → re-mark didn't re-fire:** the edge-triggered latches never reset, so
   unmarking something and re-marking it gave no second toast/audio. Every latch now
   **re-arms when its trigger goes away**: item nudges reset when the item is
   unmarked; `completedDungeon` resets when a dungeon is un-completed; the heart /
   found-count / triforce-count watermarks clamp down when the value drops. So
   re-marking fires again. (The `prior*`-based blocker reminders already did this.)

## Acceptance criteria
- [x] Recorder/PB are one-shot "you have it" nudges; no perpetual spot count.
- [x] Unmark → re-mark re-fires (item nudges, dungeon complete, triforce/found counts, hearts).
- [x] Latches re-arm on the trigger going false / count dropping.
- [x] Unit-tested; build clean.
