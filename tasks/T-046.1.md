# T-046.1 — Persist main window frame across launches

## Description
The app reopened at the OS-default position every launch. Now it remembers the
main window's frame (position + size) and restores it next launch, on whichever
display — so the user's placement sticks (user request).

SwiftUI's `WindowGroup` has no native frame-persistence modifier, so this
bridges to the underlying `NSWindow` via a small `NSViewRepresentable`
(`WindowFrameAutosave`) + a `WindowFramePersister`:
- **Restore** on window appearance from `UserDefaults` (`NSRectFromString`).
- **Save** on `didMove` / `didEndLiveResize` / `willClose` / app
  `willTerminate` (`NSStringFromRect(window.frame)`), so a real drag or resize
  and a normal quit both capture the latest frame.

Chosen over AppKit's `setFrameAutosaveName` because that only saves on
AppKit-driven moves and leans on a clean-termination flush; the explicit
observers are more robust.

## Acceptance criteria
- [x] Moving/resizing the window and relaunching reopens it at the same frame,
      on the same display.
- [x] A degenerate/empty saved rect is ignored (falls back to the default frame).
- [x] Applies to the main window only (not the Progress HUD window).
- [x] Build clean (debug + release); full suite passes; on-device verified.

## Out of scope
- Persisting the Progress HUD window's frame (it's an on-demand, resizable
  companion — default size is fine).
