# T-241 — Restore hardening — corrupt saves load safely; crash-loop guard on resume

## Problems (audit)
- A malformed save could trap: out-of-range box items (`Box.set` precondition), short `levelHints`
  (indexed by `HintTarget`), out-of-range take-any links (array indices), absurd timer elapsed
  (`Int` conversion), `Int.max` recorder index (overflow on step). The 5-second auto-resume turned
  any of these into a crash on every launch.
- Manual Load mixed in the current run's timeline/commentary/shop prices/starting items when the
  save lacked them; a spoiler line `Location contains: X` built an inverted range and trapped.

## Fix
- Sanitize on restore: `Box.sanitizedItem`, levelHints padded/truncated to `HintTarget.count`,
  take-any links limited to 0…3, recorder index bounded, timer values clamped
  (`TimerFormatting.clamped`, also guarding NaN/∞ in formatting).
- Optional sub-states missing from a save reset to defaults instead of leaking.
- Crash-loop guard: a flag is set while a resumed session is applied and first rendered; if the next
  launch still sees it, the session is moved aside (`ztracker-crashed-resume-…`) and not re-offered.
- Spoiler cave-line parser guards the coordinate range.
