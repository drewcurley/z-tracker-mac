# T-252 — Quest switch: flag and clear marks stranded on screens the new quest doesn't have

## Description
Promised in the T-237 review ("a future pass could flag specific now-invalid marks"); audit §4 found such a mark couldn't be cleared and a stranded dungeon counted as found in some places but not others.

## Acceptance criteria
- [x] A mark (other than Don't-Care) on a screen that's always-empty for the current quest is drawn with a red dashed frame and '!' (help text says to right-click), and VoiceOver reads it as invalid for this quest.
- [x] Its right-click menu offers 'Clear <mark> (no spot here in this quest)'; clearing frees a take-any's Items slot.
- [x] A stranded dungeon no longer lights its numeral or counts in Blockers — the same rule as Triforce-and-Go and the reminders — and stranded marks don't use up a mark's per-quest limit, so the real screen can be marked.
- [x] Changing quest when marks would be stranded names them (up to four, then 'and N more') and offers 'Change quest and clear them' / 'Change quest and keep them (flagged)' / Cancel.

## Notes
TrackerModel.staleMarks(for:) / isStaleMark / clearStaleMark(s). No stale marks on a custom map (no dead spots). Tests: StaleMarksTests (3), StaleMarksViewTests (2).
