# T-249 — Wire the dead hotkeys — click/scroll keys, Take-Any/Take-This, door +/−; item hotkeys honor the reachability gate

## Description
Audit §4 'visible but do nothing' hotkeys plus the promised item-hotkey gate (T-236 out-of-scope note). User-requested 2026-11-14.

## Acceptance criteria
- [x] Left/Right/Middle-click and Scroll up/down keys perform that mouse action on the hovered cell, else the keyboard cursor's cell: overworld (left action, chooser/menu, enemy picker), dungeon map (accelerator, room-type / monster / floor-drop pickers, circle; grab mode honored), Items (toggle / clear / take-any cycle / known-box toggle), dungeon item boxes (known-box toggle). No synthetic OS events (keeps the 2026-07-22 no-click-emulation decision).
- [x] Placing a take-any or wood-sword cave by hotkey arms the Contextual_TakeAny_* / TakeThis_* keys for 8 s, shown in a toast with the bound keys; a choice claims the take-any slot (via setOverworldTakeAny) or marks the cave collected + grants the wood sword / blue candle; any other key dismisses.
- [x] Repeating the take-any key cycles its claimed slot (was a bare used-toggle that desynced the Items slot); repeating the wood-sword cave key grants/ungrants the sword.
- [x] Door +/− keys step the door on that side of the cursor room (Door.Next/Prev); outer walls are a no-op.
- [x] Item hotkeys on the coast / white-sword boxes below their gate mark the item untaken (voice + picker parity); Toggle magical sword can't turn it on below 10 hearts.

## Notes
Click requests go through TrackerFocusState.clickRequest, taken once by the grid view that owns the region's popovers (never in the broadcast mirror, via the trackerIsMirror environment). Blockers have no keyboard click (popover-only). Tests: DeadControlsTests (11).
