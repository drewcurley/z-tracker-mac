# T-164 — Save/Load serialization core

## Description
Phase 1 of Save/Load (audit #4): the full state → `Codable` snapshot and back, with
round-trip tests. **No UI yet** — this is the tested foundation; the Save/Load buttons,
autosave, and startup-resume land in Phase 2 (T-165).

Approach (approved): a versioned snapshot, not direct serialization of the live
`@Observable` tree. Each sub-model gets a `Codable` `State` + `state`/`restore(_:)`,
and `TrackerModel.State` composes them:
- Elements made `Codable`: `RoomType`, `MonsterDetail`, `FloorDropDetail`, `DungeonRoom`,
  `HintZone`, `TakeAnyHeartState`, `PlayerHas`, `OverworldScreenCoordinate`,
  `DungeonBlockerAppliesTo`.
- Sub-model snapshots: `OverworldGrid`, `DungeonRoomMap`, `PlayerProgressAndTakeAnyHearts`,
  `DungeonBlockersContainer`, `DungeonTrackerInstance` (box **contents** only — structure
  is rebuilt from `kind`), and `TrackerTimer` (elapsed + started; restores **paused**).
- `TrackerModel.snapshot()` / `restore(_:)` — restore applies the HDN flag via
  `setHideDungeonNumbers` first so the tracker is rebuilt before box contents are written.

Format is JSON (versioned `version` field); **not** compatible with the Windows
reference's F# save format (deliberate — no interop need). Corrupt/wrong-size sub-arrays
are ignored on restore rather than crashing.

Out of scope (Phase 2 / later): starting-items config + Timeline history in the save.

## Acceptance criteria
- [x] Every subsystem snapshots to `Codable` state and restores.
- [x] Round-trip test (snapshot → JSON → restore) reproduces marks, room maps, doors,
      blockers, progress, dungeon boxes, flags, hints, notes, waypoints.
- [x] Corrupt-save guard: wrong-size arrays no-op instead of trapping.
- [x] Build clean; 626 tests pass.
