# T-231 — make-dmg leaves a non-native root app

## Problem
`scripts/build-app.sh` assembles into a fixed path (`./ZTrackerMac.app`). `scripts/make-dmg.sh`
builds the arches in the order `arm64` then `x86_64`, calling `build-app.sh` for each — so after a
release the **x86_64 build is left sitting in the project root**. On the Apple-Silicon dev machine
that leftover app launches under **Rosetta**, and macOS 27 warns it "won't run on a future macOS"
(Rosetta is going away in macOS 28). The developer double-clicks `./ZTrackerMac.app` and hits the
warning, even though the project is meant to be Apple-Silicon native.

The **shipped DMGs are correct** — verified: the AppleSilicon DMG is arm64, the Intel DMG is x86_64.
Only the leftover local dev copy was wrong.

## Fix
After the per-arch packaging loop, if the last-packaged arch isn't the host arch, rebuild the
project-root app for the host arch so `./ZTrackerMac.app` is always native to the dev machine.

## Acceptance criteria
- [x] After `bash scripts/make-dmg.sh` (both arches) on Apple Silicon, `lipo -archs ZTrackerMac.app/
      Contents/MacOS/ZTrackerMac` reports `arm64`.
- [x] The shipped `dist/*.dmg` binaries are unchanged (AppleSilicon → arm64, Intel → x86_64).
- [x] A single-arch invocation (`make-dmg.sh arm64` on Apple Silicon) skips the redundant rebuild.

## Out of scope
- No app-code change, no VERSION bump, no new release — this only affects the local dev artifact.
