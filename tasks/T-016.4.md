# T-016.4 — Overworld dungeon "warpable" green variant

## Description
Split out of T-016.3. On the overworld map, a dungeon tile's badge background is
**yellow** normally but **green (lime)** when that dungeon's triforce is
obtained **and** the player has the recorder — i.e. it's a recorder-warp target
(`OverworldMapTileCustomization.fs:215-225`, the `[1]`/`[3]` green bitmap
variants). This applies in **both** numbered and HDN modes (it's a warp
indicator, not a lettering concern), which is why it was pulled out of the
HDN-lettering task.

## Acceptance criteria
- [ ] Overworld dungeon badge renders green when the dungeon's triforce is
      obtained and the player has the recorder; yellow otherwise.
- [ ] Works in both default and HDN modes.
- [ ] Thread the per-slot triforce state + `HaveRecorder` into `TileView`.

## Risks / dependencies
- `playerComputedStateSummary.haveRecorder` — verify it's the real recorder
  possession (note the preserved TAG `haveRecorder` upstream quirk mirrors
  `haveLadder`; confirm which field to read before wiring).
- `OverworldMapView`/`TileView` currently don't receive the dungeon tracker;
  needs a `dungeonWarpable: (Int) -> Bool` (slot → bool) prop from
  `MainTrackerPlaceholderView`.
