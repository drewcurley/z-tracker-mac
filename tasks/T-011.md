# T-011 — Overworld routing: GYR coloring + route-line UI

## Description
`T-009`/`T-010` ported the full routing algorithm (static graph, dynamic
layer, `findAllBestPaths`) as pure, tested data/algorithm code, deliberately
not wired into any UI. This task closes the loop: surface it in
`OverworldMapView` as the reference app's "Link" feature (`docs/domain.md`
§ 4.4) — pick a destination, draw a route on the map for ~10 seconds, and
color ambiguous hinted locations green/yellow/red (GYR) based on path cost.

This also requires wiring `OverworldRoutingGraph.dynamicGraph`'s currently
hand-passed parameters (`ladder`, `raft`, `recorderWarpDestinations`,
`anyRoads`, `isMirror`, `canScreenScroll`) to live `TrackerModel`/
`TrackerOptions` state, since T-010's tests only exercise it with literal
arguments.

## Acceptance criteria
- [ ] Destination picker (specific tile, shop type, dungeon, WS/MS cave, or
      remaining open caves) — matches the reference app's own destination
      taxonomy in `OverworldRouteDrawing.fs`, not invented.
- [ ] Route line rendered on the overworld map from current position to the
      chosen destination, using `findAllBestPaths`'s predecessor chains —
      when there are multiple equal-cost paths, decide (and document) how
      ties are shown, since the reference app draws all of them.
- [ ] GYR coloring for ambiguous hinted locations, confirmed against
      `OverworldRouteDrawing.fs` to be a byproduct of relative path cost, not
      a separately invented heuristic.
- [ ] `dynamicGraph`'s parameters wired from live `TrackerModel`/
      `TrackerOptions` state (ladder/raft possession, marked any-roads,
      recorder warp destinations, mirror overworld toggle), not hand-passed.
- [ ] Tests: at minimum, a live-state wiring test (toggling ladder/raft in
      `TrackerModel` changes the computed route) plus a UI-level test that a
      chosen destination renders *a* route line without crashing.

## Out of scope
- The take-any pie-menu accelerator and hover magnifier (`docs/domain.md`
  § 4.5) — separate reference-app features, not part of routing itself.

## Risks / dependencies
- Depends on `T-010` — complete.
- Reference source for the UI half (`OverworldRouteDrawing.fs`) has not yet
  been read in depth — read it fully before implementing, per the Grounding
  & Completeness Protocol, rather than inferring behavior from the algorithm
  side alone.
