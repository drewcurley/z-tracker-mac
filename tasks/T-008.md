# T-008 — Overworld map background/terrain art

## Description
The last major open item from `T-006`/`T-007`: the overworld map's actual
terrain art, per selected quest. Investigated `Graphics.fs`'s
`overworldMapBMPs` directly: the reference app sources this from
`s_map_overworld_vanilla_strip8.png` (1280×88px = 5 sections of 256×88px
each — 4 real quest layouts + 1 unused/blank section), where each section is
a 16×8 grid of 16×11px tiles, identical in shape to the tile-mark icon strip.
The quest-to-section index is confirmed exactly via `OWQuest.fs`
(`OverworldData.fs:29-49`): `FIRST=0, SECOND=1, MIXED_FIRST=2, MIXED_SECOND=3`
(a 5th `BLANK` case exists but isn't wired up here — it maps to the
already-deferred "alternative overworld map" feature, `domain.md` § 4.1).

## Acceptance criteria
- [x] `s_map_overworld_vanilla_strip8.png` bundled as an SPM resource;
      `/NOTICE.md` updated to name both bundled assets.
- [x] `OverworldQuest.referenceAppIndex` resolves the 0...3 reference-app
      index, grounded exactly in `OverworldData.fs`'s `OWQuest.AsInt`.
- [x] `OverworldBackgroundAtlas` crops the correct 16×11 terrain tile per
      quest + column + row.
- [x] `OverworldMapView`/`TileView` render the terrain tile as the base
      layer, with the tile-mark icon composited on top only when a mark is
      set — `.unmarked` tiles show clean terrain, no gray placeholder.
- [x] Real tests cover the new atlas: 4 new test functions (dimensions,
      per-quest/column/row correctness, out-of-range handling, and a
      whole-section distinctness check — see Notes on the first version of
      this test being wrong).
- [x] Verified visually: the rendered map is recognizably the actual Zelda 1
      First Quest overworld — forests, lakes, the graveyard area all
      correctly placed, no gaps or misalignment across all 128 tiles.

## Notes
The first version of the "different quests produce different content" test
asserted a single arbitrary tile (column 5, row 3) must differ between First
and Second Quest — it failed, because that specific tile is legitimately
identical between the two quests (Zelda 1's First/Second Quest overworlds
share most terrain; only some screens differ). This was a wrong test
assumption, not a code bug — fixed by comparing the whole 16×8 section
instead of one arbitrary tile, which is the well-founded version of the
same check.

## Out of scope
- The `BLANK` quest / "alternative overworld map" custom mode (already

  `s_map_overworld_zones_strip8.png`) — the reference app's own code has
  vanilla selected (others commented out), so only vanilla is implemented.
