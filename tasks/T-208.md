# T-208 — Confirmation sounds (voice + input)

Two independent audible-confirmation channels (the buildable "confirmation sound" item from the
T-206 audit, split per the user's request into voice vs. mouse/keyboard).

## What shipped
- **Voice confirmation** (`voiceConfirmationSound`, default on) — plays when a spoken command is
  recognized (`VoiceController.execute`). The reference's `confirm_speech.wav`, byte-for-byte.
- **Input confirmation** (`inputConfirmationSound`, default off) — plays a short tick on a
  tracker edit by mouse or keyboard. Uses the reference's `reminder_clink.wav` (the Windows app
  has no dedicated input-click sound; the clink keeps the two apps cohesive).
  - **Keyboard:** every region through the one hotkey dispatcher (`ticked(...)`), excluding pure
    cursor navigation.
  - **Mouse:** overworld marks + take-any caves (`applyMark`/`applyTakeAny`) and dungeon-room
    left-clicks (`markWithInference`). (Item-box/blocker mouse clicks tick via their keyboard
    equivalents.)
- **Per-sound volume** (`voiceConfirmationVolume` / `inputConfirmationVolume`, 0…100, default
  100): a slider under each toggle in Settings, greyed when its toggle is off, applied to
  `NSSound.volume`; 0 mutes just that channel. Persists immediately on drag.
- Both sounds are bundled resources, loaded via the Sequoia-safe direct-path `AppResources`
  loader, and warmed up at launch (the reference notes the first play lags).

## Acceptance criteria
- [x] A recognized voice command plays `confirm_speech.wav` when the toggle is on.
- [x] A mouse/keyboard tracker edit plays the tick when the input toggle is on; navigation does not.
- [x] Each channel has its own volume slider that persists and mutes at 0.
- [x] Toggles + volumes persist across a quit (settings store).

## Tests
`TrackerOptionsTests`: the two toggles + two volumes default correctly.
`SettingsPersistenceTests`: the volumes persist immediately. **739 tests pass.**
