# T-238 — Save/quit/resume integrity — never silently lose or overwrite a run

## Problems (audit, confirmed in code)
1. **Critical** — the quit gate captured the model at first appear; Reset App swaps the model, so
   quitting afterwards saved the *discarded* run (or, if it was finished, deleted the new run's
   resume backstop).
2. **High** — quitting with no run in memory (resume prompt up, after "Not now", or the startup
   banner's Sparkle "Update now") deleted the unfinished `last-session.json`.
3. **High** — after "Not now", starting a new run let its first autosave overwrite the deferred run.
4. Autosave stopped at the finish, so a crash afterwards offered the *pre-finish* run with its clock
   restarted; the mirror window ran the rescue handler twice (double pause / double completed-save);
   a later real finish kept an earlier, stale "Finished in" line; unreadable saves failed silently
   and were then overwritten.

## Fix
- Quit gate re-installed on every model replacement (`onChange(of: ObjectIdentifier(model))`).
- `GameSave.quitDecision` (pure): with no run in memory, quit leaves the session untouched.
- Deferred sessions are archived as `ztracker-unfinished-…` when a new run starts or a save is
  loaded from the startup screen; Reset App archives an unfinished run the same way and clears the
  resume session (so it isn't resurrected next launch).
- The finish is autosaved (completed) so a post-finish crash doesn't resurrect the pre-finish run;
  rescue side effects run only in the real window; the "Finished in" line is replaced, not skipped.
- `checkLastSession`: an unreadable session is moved aside (`ztracker-unreadable-session-…`) and
  explained in an alert; Load shows the decode error instead of silently doing nothing.
