# T-116 — Two monsters per room

## Description
Deliberate deviation beyond the reference (which stores one `MonsterDetail` per
room), user request: a room can now hold **up to two** monsters, rendered stacked
in the top-left.

- `DungeonRoom` gains `monsterDetail2` (defaults `unmarked`) + a `monsters` list
  and a `toggleMonster(_:)` helper that keeps the pair normalized (primary filled
  before secondary; tapping a present monster removes it and promotes the secondary;
  a new tap when full replaces the secondary; `unmarked` clears both). `isDefault`
  accounts for the second slot.
- The room cell renders `room.monsters` stacked vertically (top-leading).
- `MonsterPicker` is now multi-select: taps toggle into the pair, the popover stays
  open (with a Done button) so a second can be added, and selections are badged 1/2.

No save/load impact — dungeon-room serialization isn't wired yet.

## Acceptance criteria
- [x] A room can hold two monsters; both render stacked.
- [x] Picker toggles up to two, badges order, clears on "None", has Done.
- [x] `isDefault`/accessibility account for the second monster.
- [x] Unit-tested; build + full suite clean.
