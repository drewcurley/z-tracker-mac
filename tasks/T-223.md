# T-223 — Armos eligibility + deduction

The Armos item lives on exactly one of five overworld screens, but the tracker let it be marked
anywhere. Restrict it, and deduce it once the other four are ruled out. Ships in **v1.2.5** (bundled
with the shop changes, T-224).

## Behavior
- **Restricted to the five eligible screens** (Grave / Lost Hills / Death / North Forest / East
  Forest Armos), across **every** marking path — the text menu (option hidden), graphical chooser
  (dimmed + disabled), hotkey, and voice. **Custom maps** are exempt (no fixed vanilla spots), so
  armos stays markable anywhere there.
- **Auto-deduction:** once the other four eligible screens are marked as definite non-armos things,
  the fifth is auto-marked Armos (only *adds*, never overrides a manual mark; re-derives on load).
- **Named alert:** a fresh deduction fires "**[Location] has your item**" (e.g. "East Forest Armos
  has your item") via the normal voice/visual reminder (Armos category). A **manual** mark stays
  silent — you already found it.

## Implementation
- Eligibility uses the existing `OverworldInstance.hasArmos` mask (which exactly matches the five
  screens) — not hardcoded coords. `ArmosLocation.name(column:row:)` maps each to its nickname.
- `TrackerModel.canMarkArmos(column:row:)` gates the choosers (`GraphicalTileChooser.armosAllowed`,
  the menu's Armos button), the hotkey dispatcher, voice, and a central guard in `applyMark`.
- `TrackerModel.applyArmosDeduction()` auto-marks the fifth and returns whether it *just* deduced;
  run at the top of `pollReminders` (and on `restore`). The engine fires the new
  `ReminderAnnouncement.armosLocated(name:)` only on that fresh deduction (`armosJustDeduced`).

## Tests
`ArmosTests`: mask↔name agreement, `canMarkArmos` (vanilla vs custom), deduction (four-ruled-out →
fifth; partial → none; custom-map → none), manual-mark-silent, and deduction-fires-once.
**778 tests pass.**
