# T-001 — Bootstrap `/docs/` folder

## Description
Per `playbook/AGENTS.md` § 0/§ 6, no feature work begins until Tier 1 `/docs/`
content is populated. This repo is greenfield (no app code exists yet), so
every doc is **forward-looking** rather than descriptive, per the Grounding &
Completeness Protocol (§ 6.0) — grounded not in this repo's code (there is
none) but in a dedicated, cited inventory of the reference app
(`Zelda1RandoTools`, the read-only fork this project clones feature-by-feature
— see `playbook/workspace.manifest.md`). That inventory lives primarily in
`domain.md` and is cross-referenced by every other doc.

Solo project — single-operator review per `playbook/AGENTS.md` §12, not 9
independent reviewers. See `docs/reviews/chore-bootstrap-docs/final.md`.

## Out of scope
- Actually implementing any of the above (Xcode/SPM scaffold, real Swift
  types) — tracked as `T-002`.
- The several explicitly-flagged open decisions (save-file compatibility,
  macOS save-directory location, deployment target, sprite-rendering
  approach) — intentionally left open in the docs rather than guessed; each
  should be resolved as part of the task that first needs the answer.

  directly (it's pinned locally, see `playbook/workspace.manifest.md`) rather
