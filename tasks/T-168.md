# T-168 — Hotkey contexts: hover, hint zones, dungeon items, Notes

## Description
First of three hotkey PRs closing the gap to the reference (`doc/extras.md` §hotkeys +
`whats-new.md` v1.3). T-169 covers the per-context "smarts"; T-170 the cheat sheet and
in-menu hints.

### Context source — hover wins, cursor falls back (user decision)
The reference decides what a key means from **where the mouse is hovering**; this clone
had built a keyboard cursor instead (T-134/135). Rather than pick one, both are live:
a hovered region claims the key, and the keyboard cursor is the fallback when the mouse
is outside every region.

The tie-break is the one judgement call: a **deliberate** keyboard nav (move / cycle /
voice jump) clears the hover claim, so a mouse left resting on the map can't veto
keyboard-only play; moving the mouse re-asserts it. Strict "hover always wins" would
make region-cycling silently no-op whenever the pointer happened to sit over a grid.

Hover *exit* is guarded by region: adjacent cells fire enter-then-exit out of order, so
an unguarded clear would wipe the hover its neighbour just set.

### New contexts
- **Hint zones** — hovering any hint box (9 dungeon cards + White/Magical Sword Cave)
  makes `HintZone_*` live. Checked *before* the grid regions, so hint letters can reuse
  letters bound elsewhere — the point of per-context binding.
- **Dungeon items** — the 9 dungeon cards' item boxes become a navigable region, wired
  to the existing `Item_*` bindings, with the Items grid's cyan cursor ring.
- **Notes** — a sixth region at the end of the cycle (user request).

### Notes region: park, then type
Cycling onto Notes **parks** the cursor without taking focus — a field that grabbed
focus on arrival would swallow the very cycle key being used to pass through it (user
QA). The first plain alphanumeric while parked starts typing; that character is
appended directly, because the field isn't first responder yet at keydown and the focus
change would otherwise drop it. Escape parks again without leaving the region.

While parked, **cursor-navigation globals still win over typing** (`MoveCursor*`,
`CycleRegion*`); every other global yields. Otherwise a letter bound to a toggle could
never start a note, and arrows bound to letters would strand the cursor.

### Descoped (user decision): mouse warping + click emulation
The reference nudges the OS pointer 20px off-grid and recenters it between regions.
Not built: the keyboard cursor already serves that purpose semantically, and synthetic
clicks would require the user to grant Accessibility permission and re-grant it after
every rebuild. Recorded in `docs/reference-coverage.md` § 5.

## Acceptance criteria
- [x] Hovering a region makes that region's bindings live; the cursor is the fallback.
- [x] Deliberate keyboard nav overrides a resting mouse; moving the mouse re-asserts.
- [x] Hint-zone boxes dispatch `HintZone_*`, ahead of the grid contexts.
- [x] Dungeon item boxes are navigable and markable, with a visible cursor.
- [x] Dungeon-item arrows follow the on-screen layout — left/right between dungeons,
      up/down through one dungeon's stack (shipped transposed once; now pinned by test).
- [x] Notes is the sixth cycle region: parks silently, types on the first alphanumeric,
      Escape parks again, navigation keys always escape.
