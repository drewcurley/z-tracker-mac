# T-003 — Startup screen (core)

## Description
The first real feature slice, built on the `T-002` scaffold. Implements the
reference app's startup screen (`docs/domain.md` § 4.1) for the core
happy path: pick a quest and go. This task also carries the first product
decision that diverges from strict parity — see
`docs/decisions/0003-responsive-layout-not-fixed-presets.md` — and the
`domain.md` corrections that came from verifying against the reference app's
own repo screenshots and a live VM run (not just source/doc reading).

## Acceptance criteria
- [x] `docs/decisions/0003-responsive-layout-not-fixed-presets.md` recorded;
      `domain.md`/`ux.md` updated to reflect it (not silently changed).
- [x] `domain.md` § 4.1 corrected against `Zelda1RandoTools/doc/screenshots/`
      and a live VM screenshot (the only visual source for this specific
      screen — the repo's own screenshots don't cover it).
- [x] `TrackerModel` gains `heartShuffle: Bool` and `hideDungeonNumbers: Bool`
      published state alongside the existing `quest` selection.
- [x] A `StartupView` SwiftUI view renders: title, Heart Shuffle / Hide
      Dungeon Numbers toggles, the 4 quest-start buttons, a disabled "Start
      from a previously saved state" button (save/load doesn't exist yet —
      see Out of scope), and a tip/factoid display.
- [x] Layout is responsive (no fixed pixel window size) per ADR 0003 —
      verified by launching the built app and resizing it (narrow/default/
      wide screenshots), confirming content reflows/centers/truncates
      gracefully rather than clipping or overflowing.
- [x] Selecting a quest navigates to a placeholder main-tracker view (real
      main tracker view is a future task) carrying the selected quest +
      toggle state — verified end-to-end via an actual click on the running
      app, not just read from source.
- [x] Real Swift Testing tests cover the new model state transitions (6 new
      tests: toggles default/independent/initializer, tip list
      non-empty/no-duplicates/random-is-from-list; 11/11 passing overall).
- [x] `domain.md` § 4.1 annotated per-bullet with what's implemented here vs.
      deferred (this doc doubles as the living parity checklist).

## Out of scope (tracked as follow-ups)
- The embedded 3-column settings panel (Overworld/Reminders/Other, ~30
  toggles) — genuinely large, self-contained — tracked as `T-004`.
- The "alternative overworld map" custom-ROM-hack mode (niche, `other.md`
  scope) — not scoped yet.
- Actual save-file loading for "Start from a previously saved state" — the
  button exists but is disabled/labeled until persistence is implemented
  (depends on the save-format compatibility decision still open in
  `data-model.md` § 4).
- The full, exhaustive original tip/factoid list — a small illustrative
  subset is used for now, explicitly labeled as a subset, not invented as
  complete; the full list lives in the reference app's `DungeonData.fs`
  and should be extracted in a follow-up, not guessed.
- The real main tracker view — a placeholder stands in for it here.

## Risks / dependencies
- Depends on `T-002` (scaffold) — complete.
- The disabled "start from saved state" button is a partial UI element by
  design (clearly labeled, not silently broken) — flagged so it isn't
  mistaken for forgotten work.
