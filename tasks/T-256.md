# T-256 — Popover-crash workaround: dungeon room pickers in a panel instead of NSPopover

## Description
Promised in T-139/T-145 and the popover-consolidation review: the dungeon room-type / monster / floor-drop pickers crashed intermittently in AppKit's NSPopover/ViewBridge on the macOS 27 beta, esp. when backgrounded. T-145 reduced the anchors from 192 to 3; the follow-up (a custom overlay replacing NSPopover) was deferred and never filed.

## Acceptance criteria
- [x] The three room pickers present in a borderless child panel (no NSPopover, no ViewBridge), centered below the room (above it if there's no room), kept on screen, honoring the UI zoom.
- [x] It opens without animation; closes on Esc, a click outside (swallowed, as a transient popover's is), or the app losing focus; choosing an item closes it as before; the monster picker stays open for a second monster.
- [x] Clicks in the panel work on the first click (it can take key); focus returns to the tracker when it closes.

## Notes
No crash report was ever captured, so this removes the reported crash path rather than a reproduced one. Other popovers (overworld chooser, item picker, etc.) are unchanged — move them to pickerPanel if crashes are seen there. Tests: PickerPanelTests (3, placement + zoom).
