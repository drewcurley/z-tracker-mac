# T-156 — Door inference default on

## Description
Live QA: "door inference doesn't work in voice." Diagnosed (unit test) that the
apply path DOES infer the connecting door when `inferDoors: true` — the issue was
`doDoorInference` defaulting **false**. Default is now **true**: marking a room
adjacent to one already marked auto-opens the entry door, which is exactly what
makes voice "mark, move, mark" draw the connecting doors ("traveling = door").

**Notes:** existing installs that already persisted `false` keep it (toggle on in
Settings). Pure movement-without-marking inference (infer a door when the cursor
moves between two already-marked rooms) is deferred — the marking path covers the
common flow.
