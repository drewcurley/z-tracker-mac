# T-110 — Item-cave dim derives from collection state

## Description
The armos, White-Sword-Item cave (SWORD2) and Magical-Sword cave (SWORD3) tiles
were dimming the moment they were placed on the map (a blanket auto-`setUsed(true)`
on any `isUsedToggleable` mark, plus those three wrongly being in the toggleable
set). Per the reference (`OverworldMapTileCustomization.fs:221-260`), these three
dim from *model* state — the item behind them being collected — not from a map
toggle:

- armos → `armosBox.isDone`
- SWORD2 (White-Sword-Item cave) → `sword2Box.isDone`
- SWORD3 (Magical-Sword cave) → player has the magical sword (`swordLevel == 3`)

The reference `toggleables` set is exactly take-any, the **wood**-sword cave
(SWORD1), hint shop, the three sized secrets, and the letter — so those three
caves were removed from `isUsedToggleable`. Placement defaults also now match the
reference: secrets / letter / hint shop place **dark**; take-any and the wood-sword
cave place **bright** (`placesUsedWhenMarked`).

This fixes both #3 (map tile dims on placement) and #4 (Spot Summary white/magical
swords don't dim when the sword is collected elsewhere): `SpotSummary.compute` now
takes `armosDone` / `whiteSwordItemDone` / `hasMagicalSword` and derives those
uniques' `done` from them.

## Acceptance criteria
- [x] Armos / SWORD2 / SWORD3 tiles stay bright when placed, dim only when the item
      is collected (box done / magical sword held).
- [x] Wood-sword cave places bright and stays a manual toggle; secrets/letter/hint
      shop still place dark.
- [x] Spot Summary reflects the same derived done-state for those three.
- [x] `isUsedToggleable` matches the reference `toggleables` set.
- [x] Unit-tested; build + full suite clean.
