# T-186 — Timeline not restored on save/load

## Bug
Saving an active session and restoring it later brought back marks/items but **not the
run timeline** (GameTimelineView) — the acquisition times were gone.

## Root cause
`TrackerModel.State` (the save snapshot) included overworld, room maps, tracker,
blockers, and progress — but **not `timeline`**. The timeline's `acquiredAt` (when each
item was collected) is historical and can't be re-derived from current state, so on
restore it started empty. (The class doc even claimed the timeline was part of the
saved state; it wasn't.)

## Fix
- `TimelineModel` gains a `Codable` `State` (+ `state` / `restore(_:)`), with
  `TimelineEvent` and `OverworldRemainingSample` made `Codable`.
- `TrackerModel.State` gains `timeline: TimelineModel.State?` — **optional**, so saves
  written before this fix still decode (they restore with an empty timeline, as before).
  `snapshot()` writes it; `restore()` applies it when present.
- `recordTimeline` (the 1 Hz poll) re-derives the acquired set + locations from current
  state, so after restore it *keeps* the restored acquisition times (only stamps newly
  acquired events) and continues the series correctly.

## Tests
`SaveStateRoundTripTests`: the round trip now records + asserts timeline events
(`acquiredAt`, `acquiredLocation`, `latestSeconds`); a new test strips the `timeline`
key to prove a pre-fix save still decodes with an empty timeline. 720 tests pass.

## QA checklist
- [ ] Start a run, collect a few items over time, Save…, quit, reopen, Load — the
      timeline shows the same events at the same times.
- [ ] Loading an older save (from before this build) still works (empty timeline, no crash).
