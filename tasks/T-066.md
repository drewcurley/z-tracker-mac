# T-066 — Take-any tile ⇄ Items-group heart-slot sync

## Description
Bug (from T-057): marking a take-any tile recorded its item into the *next free*
Items-group heart slot with no link back to the tile. So re-marking the same
tile a different way recorded a **second** slot, and changing/clearing the tile
left its slot stranded.

Fix: each `.takeAny` tile stores a link to the one Items-group slot it owns
(`OverworldGrid.takeAnySlotLinks`). All take-any edits route through the model,
which keeps the two in sync:

- Marking / re-marking a tile reuses its own slot (never a second).
- `.untaken` (or changing the tile to another mark, or clearing it) frees the
  slot back to an empty heart.
- Left-click on a take-any tile cycles its state, in sync.
- Editing a heart box directly reflects back onto the linked tile's dim.
- A newly-claimed tile skips slots already owned by a tile, so it never
  double-links.
- Groundhog reset clears both the hearts and the links.

## Acceptance criteria
- [x] Re-marking a take-any tile updates its own slot, never fills a second.
- [x] Changing a take-any tile to another mark (or clearing) empties its slot.
- [x] Setting a take-any tile to Unclaimed frees its slot.
- [x] Left-click cycles a take-any tile's state and its slot together.
- [x] Editing a linked heart box updates the tile's dim.
- [x] Groundhog reset clears hearts + links; the tile mark is kept.
