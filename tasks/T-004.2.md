# T-004.2 — Wire "Shops before dungeons"

## Description
The startup "Shops before dungeons" setting (`options.shopsBeforeDungeons`) was
stored + bound but read by nothing. Wired it into the overworld tile-selection
popup: when on, the **Shop** submenu leads (before Dungeon); when off, the popup
leads with Dungeon (its previous order). Matches the reference
`Overworld.ShopsFirst` — "the grid starts with shops when this is checked"
(`OptionsMenu.fs:49`, `WPFUI.fs:667`).

The Shop submenu (and its conditional "Shop — 2nd item" submenu, T-060) was
extracted to a `shopMenus(column:row:)` helper so it can be emitted at the top
of the popup or in its default position based on the flag.

Default is `true` (shops first), matching the reference's live default
(`TrackerModelOptions.fs:17`).

## Acceptance criteria
- [x] `options.shopsBeforeDungeons == true` → the tile popup lists Shop before
      Dungeon; `false` → Dungeon before Shop (the prior order).
- [x] The "Shop — 2nd item" submenu still appears (only for a marked shop) in
      whichever position Shop takes.
- [x] Build clean (debug + release); full suite passes; on-device verified (ON
      case: popup leads with Shop).

## Out of scope
- Persisting this setting across launches (only Reminders persist so far,
  T-004.1) — session-only like the other non-reminder options.
- Reproducing the reference's flat icon-grid picker shape (this app uses a
  hierarchical context menu — a pre-existing, accepted deviation).
