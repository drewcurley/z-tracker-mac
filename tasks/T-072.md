# T-072 — Dungeon drag-paint

## Description
First power tool: hold a button and drag across rooms to paint them, per the
reference `dragBehavior` (`DungeonUI.fs:1357-1382`):
- **left** drag over an off-the-map room → unmarked (paint the map back on)
- **right** drag over an unmarked room → off-the-map (paint it off)
- **⌥ / middle** drag over an unmarked room → the default room, completed

- `DungeonRoomMap.dragPaint(_:col:row:)` (pure, unit-tested) applies the per-room
  rule; a non-matching room is a no-op.
- `RoomMouseCatcher` gains opt-in drag support (`dragContext` + `onDragPaint`):
  it maps the cursor to the room under it (via this cell's position + the grid
  pitch, in a flipped view) and paints. A 4pt threshold separates a click from a
  drag. Doors don't pass a drag context, so their behavior is unchanged.

**Click-timing de-risk:** the primary **left**-click still fires on mouse-**down**
(unchanged — left-click and left-drag don't conflict). Only **right/middle** on
rooms defer to mouse-**up** (their click — picker / circle — would otherwise clash
with a right/middle drag), firing only when it wasn't a drag.

## Acceptance criteria
- [x] `dragPaint` matches the reference rules (left/right/⌥·middle; no-ops

- [x] Drag support is opt-in; doors unchanged; left-click stays on mouse-down.
- [x] Build clean; grid renders; no crash.
- [ ] Live drag + right/middle-release behavior verified by the user (can't
