# T-160 — Snappier selection popovers

## Description
The dungeon-room pickers (T-145) were made to snap open by presenting inside a
`disablesAnimations` transaction; the user asked for the same treatment on the other
selection popovers, which felt "just as long". Extracted the treatment into one shared
helper `presentPopoverWithoutAnimation` and applied it to every click / right-click /
VoiceOver path that presents a selection popover.

Covered: dungeon item boxes and the coast / white-sword / armos picker boxes (all share
`BoxView`), blockers kind + applies-to pickers, the Armos / white-sword-cave in-place
item prompt, the dungeon-number picker, the hint-zone picker, and the dungeon-room
pickers (refactored off their inline transaction onto the shared helper).

## Scope boundary
Disables the SwiftUI transition only. AppKit still animates the `NSPopover` frame at the
window-server level — removing that residual would need a custom `NSPopover`, a larger
change deferred until/unless the snap isn't enough. Info/settings panels (recorder
settings, More Settings, voice picker, hint decoder, spot summary, minimap) are left
as-is — not latency-sensitive selection pickers.

## Acceptance criteria
- [x] One shared `presentPopoverWithoutAnimation` helper; no per-site inline transactions.
- [x] Every named picker (dungeon items, coast/white-sword/armos, blockers, dungeon
      number, hint zone, dungeon rooms) presents through it, on mouse + a11y paths.
- [x] Build clean; 621 tests pass.
- [x] User QA on a live run: feels ok.
