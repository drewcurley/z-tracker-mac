# T-019.6 — Dungeon room editing (D2a): left-click + right-click picker

## Description
First editing slice over the D1 render (T-019.5). Implements the reference's
plain **left-click** room behavior and moves the room-type picker to
**right-click**, freeing left-click for the reference gestures
(`Z1R_WPF/DungeonUI.fs:1418-1450`, `:293`):

- **Left-click** (`DungeonRoomGesture.leftClick`, pure + unit-tested):
  1. First interaction with a dungeon → drops the entrance (from south),
     completed (the per-level `isFirstTimeClickingAnyRoom` accelerator).
  2. Touched dungeon + unknown room → marks the default room (MaybePushBlock),
     completed.
  3. Entrance room → cycles its arrow S→W→N→E→S.
  4. Off-the-map → paints back to unmarked.
  5. Otherwise → toggles completedness.
- **Right-click** → the room-type picker (was left-click in D1).
- A new `RoomMouseCatcher` (NSView) provides precise button + modifier input
  SwiftUI can't (left / right / Shift+left / Shift+right / middle), gated like
  `RightClickCatcher` so scroll/hover fall through to the page ScrollView.
  Shift+click (monster / floor-drop) and middle (circle / brightness) are wired
  in D2b.

`firstInteractionDone` added to `DungeonRoomMap` (knowledge; persists across a
groundhog reset) to drive the entrance accelerator. VoiceOver: the cell's default
action is the primary left-click; a named "Set room type" action opens the picker.

## Acceptance criteria
- [x] Left-click resolves per the reference branch order (accelerator, entrance,
      cycle, off-map recover, completion toggle).
- [x] First left-click in a dungeon places the entrance; subsequent clicks cycle
      it rather than re-placing.
- [x] Right-click opens the room-type picker; picking still enforces transport
      limits (via `setRoom`) and clears the first-interaction flag.
- [x] Mouse catcher claims only its button-downs; scroll/hover pass through.
- [x] VoiceOver: primary action toggles/marks; named action sets room type;
      value announces completion.
- [x] Unit tests for the resolver, the map integration, and the catcher gating;
      build clean (debug + release); on-device render verified (no regression).
