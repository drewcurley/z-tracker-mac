# T-019.8 — Dungeon doors (D3)

## Description
Renders and wires the door (wall) segments between adjacent rooms over the D0
door model (`DoorState`, T-019.3), matching the reference
(`DungeonUI.fs:717-831`, `Dungeon.fs:13-56`).

- **Layout**: the room grid moved from stacked HStack/VStacks to an absolutely
  positioned `ZStack` (rooms + doors share one coordinate system), because doors
  live in the inter-room gaps that a plain stack can't address. Room positions
  are unchanged; the header still aligns per column.
- **DungeonDoorView** renders each state in the reference palette: yes = green
  block, no = red wall line, yellow / purple = colored blocks, unknown = a faint
  stub (hidden when either adjacent room is off-map).
- **Gestures** (`RoomMouseCatcher`, per door): left = toggle YES, right = toggle
  NO, middle = toggle YELLOW, Shift+left = prev, Shift+right = next.
- **Model**: `DoorState.toggled(to:)` + `DungeonRoomMap.DoorAxis` / unified
  `door(_:col:row:)` / `setDoor(_:axis:col:row:)`.
- VoiceOver: each door is a button announcing its span + state, with toggle-open
  and cycle actions.

## Acceptance criteria
- [x] Doors render in the gaps on both axes in the reference colors; `no` is a
      wall line, `unknown` is faint and hidden on off-map borders.
- [x] Left/right/middle toggle YES/NO/YELLOW; Shift+left/right cycle prev/next.
- [x] The grid refactor preserves room positions, the header alignment, and the
      map-width cap.
- [x] Unit tests for toggle/cycle/accessor/traversible; build clean; on-device
      visually verified (all five states, both axes, positioning).
