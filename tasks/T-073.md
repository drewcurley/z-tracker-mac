# T-073 — Dungeon GRAB model foundation

## Description
The algorithmic core of the second power tool (GRAB — move a dungeon segment),
built and tested ahead of the interaction (like D0 preceded the room UI). Ported
from the reference `GrabHelper` (`Dungeon.fs:61-149`):

- `DungeonRoomMap.contiguousRegion(col:row:)` — BFS flood-fill of the non-empty
  rooms connected to a start room by 4-adjacency (the blob a grab picks up).
- `DungeonRoomMap.moveRegion(_:byColumns:rows:)` — cut the region (cells emptied,
  touching doors cleared), then paste the rooms + circles + each set internal door
  at the offset; off-grid cells drop, overlaps overwrite. Transport counts are
  recomputed after the move.
- `DungeonRoomMap.dropWouldOverwrite(_:byColumns:rows:)` — the reference "warn"
  check (a region cell landing on an existing room) that will drive the keep/undo
  prompt.
- `RoomCoord` — a `Hashable` grid coordinate for the region set.

## Acceptance criteria
- [x] Contiguous region = the connected non-empty blob (off-map rooms break it;
      empty start → empty).
- [x] Move relocates rooms + circles + set internal doors and clears the source;
      off-grid cells drop; transport counts stay consistent.
- [x] Overwrite detection flags a landing on an existing room.
- [x] Unit tests for all of the above; build clean.
- [ ] Interaction (grab mode, drag-to-drop, preview highlight, keep/undo prompt)
      — a later slice, to design + verify with the user.
