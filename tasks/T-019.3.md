# T-019.3 — Room-map model foundation (D0)

## Description
The pure-TrackerCore model under the dungeon room-map grid (the "D0" slice that
unblocks the render/editing slices). Ported verbatim from the reference's
`DungeonRoomState.fs` / `Dungeon.fs` / `DungeonUI.fs` per-dungeon state.

- **`DoorState`** (`DungeonDoorState.swift`) — 5 states (unknown/no/yes/yellow/
  purple, raw 0–4 for the future save), `next`/`prev` cycle, `isTraversible`,
  reference `rgb`.
- **`RoomType`** (34), **`MonsterDetail`** (32), **`FloorDropDetail`** (9)
  (`DungeonRoomTypes.swift`) — case names match the reference so the save
  hot-key tokens derive exactly (`RoomType_Bow` …); reference `displayDescription`;
  `RoomType.isOldMan` / `nextEntranceRoom` (S→W→N→E) / `transportNumber`.
- **`DungeonRoom`** (`DungeonRoom.swift`) — the 5 room fields + `isEmpty`,
  `isDefault` (the save `null` sentinel).
- **`DungeonRoomMap`** (`DungeonRoomMap.swift`) — one per dungeon: 8×8 rooms,
  `horizontalDoors[7][8]` + `verticalDoors[8][7]`, a per-room circle flag, and
  the transport-pair counter with the "reject a third copy" legality
  (`SetNewValue`'s `usedTransports <> 2`). Derives `oldManCount`, `hasOffMapRoom`.
- **Model wiring:** `TrackerModel.dungeonRoomMaps` (9). Grid *knowledge*, so a
  groundhog reset keeps it (like the overworld marks).

## Acceptance criteria
- [x] Enum counts match the reference (RoomType 34, Monster 32, FloorDrop 9,
      Door 5); hot-key tokens round-trip; unknown → unmarked.
- [x] `isOldMan`, entrance cycle, `transportNumber`, door cycle/traversibility,
      `DungeonRoom.isEmpty`/`isDefault` — all unit-tested.
- [x] `DungeonRoomMap`: room get/set, doors, circle, `oldManCount`; transport
      legality (two allowed, third rejected, counts track, re-mark allowed).
- [x] `TrackerModel.dungeonRoomMaps` (9) survive a groundhog reset.
- [x] Build clean (debug + release); full suite passes (353).

## Out of scope (later D-slices)
- Rendering the grid (D1), room/door editing + pickers (D2/D3), door inference,
  the Summary tab, and power tools. Monster names taken verbatim from the
  reference `DisplayDescription`; any ambiguous ones (e.g. "Rupee Boss") are the
  reference's own labels.
