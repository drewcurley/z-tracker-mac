# T-019.11 — Dungeon trackpad gestures

## Description
User feedback after the D2/D3 gestures shipped: (1) they used the Windows app's
**scroll-to-cycle on doors** heavily and want the equivalent on Mac; (2) they have
**no middle button**, so the middle-click behaviors (room circle/brightness, door
yellow) were unreachable. Restores the reference wheel + middle gestures using
Mac-native input, keeping Shift+click as an accessible fallback.

Gesture map added to `RoomMouseCatcher`:
- **two-finger scroll** — the reference wheel (`DungeonUI.fs:1348-1356`, `:745-748`):
  room scroll ↑ = monster picker, ↓ = floor-drop picker; door scroll = cycle
  (↑ = prev, ↓ = next). One action per trackpad flick (phase-gated, momentum
  ignored); classic mouse wheel fires per detent.
- **⌥-click** — the reference middle-click (`:738-742`, `:1466-1471`): room = circle
  (no drop) / floor-drop brightness; door = toggle yellow.
- Shift+click retained as the fallback (chosen scheme, user picked scroll for the
  primary shift-free room path).

`hitTest` now also claims `.scrollWheel`, so scroll over a room/door is consumed
to drive the gesture — the deliberate page-scroll tradeoff (doors are tiny; the
room grid is larger — accepted by the user).

## Acceptance criteria
- [x] Scroll cycles doors and opens the room monster/floor-drop pickers.
- [x] ⌥-click toggles room circle/brightness and door yellow (no middle needed).
- [x] One picker/cycle per trackpad gesture (no repeats from momentum).
- [x] Shift+click + right-click paths unchanged.
- [x] Build clean; catcher `intercepts` test updated for scroll.
- [x] Scroll DIRECTION confirmed by the user (up = monster, down = floor drop).
- [x] Page-scroll feel with the room dead-zone confirmed acceptable by the user.
