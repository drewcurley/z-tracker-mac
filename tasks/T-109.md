# T-109 — Warn on close while timer running

## Description
It was possible to quit the app mid-run with the timer still ticking and lose it
silently. A new setting (**default on**, beyond the reference) shows a confirmation
alert — "The run timer is still running. Quit anyway?" — when the app is asked to
terminate while `timer.isRunning`. Canceling keeps the app open.

Wiring:
- `TrackerOptions.warnOnCloseWhileTimerRunning: Bool` (default `true`, persisted with
  the other startup bools; also toggleable mid-game in the Settings panel under Other).
- `AppDelegate.applicationShouldTerminate` consults `AppDelegate.confirmQuit`, a
  closure `ContentView` installs on appear that captures the hoisted timer + options
  and calls `confirmQuitWhileTimerRunning(timer:options:)` (an `NSAlert`).
- `TrackerTimer.hardReset()` returns the timer to its pristine pre-Go state; Reset App
  now resets the hoisted timer in place instead of replacing the instance, so the
  captured closure stays valid across a reset.

## Acceptance criteria
- [x] Setting exists, defaults on, persists, and shows in the Settings panel.
- [x] Quitting while the timer runs (and the setting is on) prompts; Cancel aborts quit.
- [x] Quitting is unimpeded when the timer isn't running or the setting is off.
- [x] Reset App keeps the timer instance (quit guard survives a reset).
- [x] Unit-tested (`hardReset`, default value); build + full suite clean.
