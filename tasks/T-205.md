# T-205 — Overworld chooser UX batch

Three related overworld tile-selection tweaks (user requests):

## 1. Left-click F16 → coast-item picker
The coast item is always on the coast screen (**F16** = col 15, row 5), so a left-click there
opens the coast-item picker directly (the `ladderBox`, which already excludes the ladder).
Generalized the T-106 in-place item prompt (`ItemPromptTarget`) from an `isArmos: Bool` to a
`PromptBox { armos, whiteSword, coast }`. Right-click still gives the normal tile menu. The
prompt is deferred a runloop tick (like Armos/White-Sword) — presenting a popover synchronously
inside the tap gesture no-ops (that was the "can't select F16" bug in the first cut).

## 2. Live hover label in the graphical chooser
The chooser header now updates **instantly** to the icon under the pointer (no waiting on the
system tooltip delay). Tracked by label string with race-safe clear-on-exit; the tooltip stays.

## 3. Graphical overworld chooser on by default
`graphicalOverworldChooser` default flipped **false → true** (graphics read faster; the Windows
app is graphical-only). Existing installs keep their saved choice (persisted); only fresh
installs get the new default.

## Tests
`ZonesAndCoordsTests`: the coast constants (`OverworldMapView.coastColumn/Row`) label as "F16".
732 tests pass. All three QA'd on device (user: "both look good"). `VERSION` → 0.8.4.
