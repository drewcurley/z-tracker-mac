# T-010 — Overworld routing: dynamic layer + pathfinding

## Description
`T-009` ported the static adjacency graph. This task ports the remaining
two pieces before GYR/routing-lines can reach the UI:
1. The **dynamic** layer (`OverworldRouting.fs:351-411`, `populateDynamic`):
   screen-scroll variants for mirrored vs. normal overworld orientation, and
   dynamic edges for recorder-warp destinations and marked any-roads (which
   depend on live tracker state, not just item possession).
2. The **pathfinding search** itself (`findAllBestPaths`,
   `OverworldRouting.fs:426-465`): a priority-queue breadth-first search
   that returns every optimal path (there can be ties) from a source vertex
   to a target, not just one.

## Acceptance criteria
- [ ] Dynamic edges ported: screen-scroll tables (`staticMirrorScreenScrolls`,
      `staticNormalScreenScrolls`) and the recorder-warp/any-road edge
      generation (`addExtra`), grounded exactly, verified by the same
      call-count-comparison discipline `T-009` established.
- [ ] `findAllBestPaths` ported faithfully, including its tie-handling
      (multiple equal-cost predecessors) — this is the part of the
      algorithm most likely to have subtle bugs if paraphrased rather than
      transcribed; port structure, don't "clean up" the algorithm shape.
- [ ] Tests: known-route regression tests (e.g. a hand-verified shortest
      path between two specific screens with specific items held) — not
      just "it returns something."
- [ ] Still not wired into the UI (GYR coloring / route lines) — that's the
      next follow-up, once the algorithm itself is verified correct in
      isolation.

## Out of scope
- GYR tile coloring and route-line rendering in `OverworldMapView` — a
  further follow-up once this task's algorithm is verified.
- The take-any pie-menu accelerator and hover magnifier.

## Risks / dependencies
- Depends on `T-009` — complete.
- Same transcription-risk profile as `T-009`, arguably higher: the
  pathfinding algorithm's correctness is harder to spot-check by eye than a
  static edge list. Prioritize the known-route regression tests.
