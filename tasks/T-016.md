# T-016 — HDN mode: dungeon labeling + basement-stair metadata

## Description
"Hide Dungeon Numbers" is a whole alternate randomizer mode where dungeon
*identities* are shuffled/hidden and the player labels discovered dungeons
A-H by color/letter as they go — a large orthogonal complexity multiplier
that roughly doubles most dungeon-related code paths with
quest/kind-dependent branching (per the `T-012` scoping read-through),
deliberately deferred out of `T-013` to keep the DEFAULT-mode core clean.

Covers, all in `TrackerModel.fs`:
- `DungeonTrackerInstanceKind.HIDE_DUNGEON_NUMBERS`'s box-count table
  (dungeons 0-7 get 3 boxes each, dungeon 8 gets 2 — vs. DEFAULT's mixed
  2/3 table) and `Dungeon.IsComplete`'s HDN branch (`:789-813`) — 3 boxes
  done, OR 2 boxes done when the dungeon's assigned `LabelChar` is in a
  quest-dependent whitelist string of "two-boxer" labels.
- `Color`/`LabelChar` per-dungeon player-assigned labeling (`:816-818`).
- `StairKind`/`BoxOwner` enums (`:587-597`) and `CurrentlyHasBasementStair`
  (`:607-632`, ~26 lines) — which dungeon-room-grid cell a box's stair icon
  renders in, keyed on quest + dungeon-label-char + box-index (vanilla
  dungeon-shape knowledge, applies in both DEFAULT and HDN modes but is
  most load-bearing for HDN's letter-based dungeon identification).
- HDN-mode's index shift in `GetTriforceHaves()` (`:823-836`) — maps from a
  dungeon's assigned `LabelChar` back to triforce-piece-index.
