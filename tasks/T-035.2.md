# T-035.2 — Map-overlay toggles: open-caves + money

## Description
The first two top-section map-overlay toggles, with the user's interaction
model: **hover an icon → preview the highlight on the map; click → lock it on**
(no separate checkboxes).

- **`OverworldOverlayState`** (`@Observable`): per-overlay `locked` set +
  transient `hovered`; `isActive = locked || hovered`. Owned by
  `MainTrackerPlaceholderView`, shared with the chrome icons + the map.
- **Open caves** (`highlightOpenCavesCB`, `OverworldItemGridUI.fs:456-466`):
  highlight unmarked `nothingable` screens **until** the wood sword cave is
  found or the player has a sword + candle; **after** that, only the unclaimed
  Armos spots.
- **Money** (`showLocatorRupees`, `WPFUI.fs:1467-1483`): highlight Money Making
  Game, Unknown Secret, and priced money secrets. (Priced secrets aren't
  settable in the UI yet, so today this is MMG + Unknown Secret; the sized-
  secret value check is in place for when that lands — with the claimed-state
  model, T-036 note.)
- Icons: a `mountain.2.fill` SF Symbol (open caves) + the `rupee` atlas sprite
  (money) in the item-grid chrome; hover/click wired to the overlay state,
  locked state shown green. `OverworldMapView` draws a green border+fill on
  qualifying tiles for any active overlay.

## Acceptance criteria
- [x] `OverworldOverlayState` hover-preview + click-lock; `isActive` = either.
- [x] Pure `isMoneyTile` / `isOpenCaveTile` / `openCavesPastEarlyGame`
      predicates, tested.
- [x] Two chrome toggle icons wired; the map highlights qualifying tiles.
- [x] On-device verified: locking open-caves highlights the unmarked
      nothingable screens.

## Out of scope
- Zones + Coords overlays (T-035.3); priced-secret value UI (with claimed-state).
