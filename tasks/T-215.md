# T-215 — Commentary Mode

When two runners race the same seed, the commentator wants to track **who has seen / knows** each
element. Commentary Mode adds a transparent, commentator-only layer over the tracker recording, per
element, whether runner 1, runner 2, both, or neither has that knowledge. It is **never shown to
stream viewers** — it lives only in the commentator's tracker.

## Behavior
- **Gesture (app-wide):** ⌥-click = runner 1, ⌥-right-click = runner 2. Toggling cycles that
  runner's bit (neither → R1 → both → R2 → …). Only active while Commentary Mode is on; normal
  marking is untouched.
- **Two encodings (selectable):** corner **pips** (one triangle per runner) or a colored **edge
  border** (one runner colors the frame; both splits it left/right). Chosen in Settings.
- **Per-session runner identities:** editable names + colors (default red / blue), saved with the
  game (a race runs long).
- **Five surfaces, one store:** overworld tiles, dungeon item boxes, the collectible item grid,
  dungeon room maps, and the blockers grid.
- **Legend:** a COMMENTARY banner with both runners' name chips shows in the open band above the
  overworld while the mode is on. A "Clear all commentary marks" action lives in the Commentary
  settings subscreen (keeps names/colors).

## Implementation
- **`CommentaryLayer` (TrackerCore, `@Observable`):** a single string-keyed store
  `marks: [String: CommentaryKnowledge]` (an `OptionSet` of `{runner1, runner2}`), served by a
  namespaced key per surface: `ow:c,r`, `box:d,b`, `item:id`, `room:d,c,r`, `blk:d,s`. Absent key =
  neither (kept sparse). Runner names/colors live here too. Saved via `State` in the model snapshot
  (optional → back-compatible with old saves).
- **`TrackerOptions`:** `commentaryMode: Bool` (persisted) + `commentaryEncoding` (persisted).
- **Views (`CommentaryOverlay.swift`):** `CommentaryTileOverlay` (pips/border, `allowsHitTesting(false)`),
  `OptionRightClickCatcher` (claims only ⌥+right so plain right-click still works), the
  `.commentaryCell(…)` modifier, `CommentaryLegendBanner`, and hex↔Color helpers. Each surface
  hoists its knowledge into locals and gates on `commentaryMode`.
- **Room maps** required moving the room "circle"/brightness and door "yellow" off ⌥ onto
  **⌘-click / ⌘-drag** (`RoomMouseCatcher` gained `.commandLeft` + `.optionLeft/.optionRight`), so
  ⌥ is unambiguously the commentary modifier everywhere. Room pips use the free corners (R1
  bottom-left, R2 top-right) since the monster owns top-left and the drop bottom-right.
- **Settings:** a dedicated **Commentary…** subscreen window (mode toggle, encoding picker, runner
  name/color editors, clear-all), opened from the settings panel.

## Tests
`CommentaryLayerTests` — toggle cycle, sparse-clear, clear-keeps-identities, per-surface key
distinctness, and save/restore round-trip. **758 tests pass.**
