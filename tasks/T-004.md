# T-004 — Startup screen embedded settings panel

## Description
`T-003` deliberately scoped out the reference app's 3-column embedded
settings panel (`docs/domain.md` § 4.1) — ~30 toggles across Overworld
settings, Dungeon settings, Reminders (with a Voice/Visual matrix for the 7
categories in § 4.10), and Other (including the broadcast-window size
radio group, which stays fixed-size per ADR 0003 even though the rest of the
layout is responsive). This task builds that panel.

## Acceptance criteria
- [ ] Every toggle enumerated in `docs/domain.md` § 4.1's settings-panel
      bullet list has a corresponding model field and a real UI control —
      no silent subset.
- [ ] Model fields live in `TrackerCore` (likely a dedicated `TrackerOptions`
      type rather than growing `TrackerModel` unboundedly — a design call
      for whoever picks this up, not pre-decided here).
- [ ] Panel is responsive per ADR 0003, consistent with `StartupView`.
- [ ] Real tests cover the new state.
- [ ] `domain.md` § 4.1's settings-panel bullet updated from "not
      implemented, tracked as T-004" to implemented, or partially with the
      remainder re-scoped explicitly.

## Out of scope
- Making any of these toggles actually *do* anything yet beyond holding
  state (e.g. "Draw routes" doesn't need working route-drawing yet — that's
  the overworld-map feature's job). This task is about the settings surface
  existing and being persisted-eventually-capable, not every downstream effect.

## Risks / dependencies
- Depends on `T-003` (this repo's startup screen core) — complete.
