# T-234 — Dual-pane per-runner Spot Summary

When **commentary mode** is on, the Spot Summary (inline popover **and** breakout window) splits into
two columns — one per runner — so a commentator can see, at a glance, how much of each spot type each
runner has been shown. Ships as **v1.2.10**.

## Behavior
- **Commentary on** → two columns divided by a line, each headed by the runner's **name on their
  color chip** (the same red/blue as the map's commentary indicators). Every section is duplicated
  per column (Unique locations, Secrets remaining, Non-unique locations), and each column tallies
  **only the spots that runner has been shown** (`CommentaryLayer.knowledge(column:row:)`).
- **Commentary off** → the single combined tally, exactly as before.
- **Breakout window is responsive:** the two panes sit **side-by-side** (and scale to fill the
  window, as today) while there's room; once the window is too narrow to show them side-by-side
  without shrinking past the minimum scale, they **stack vertically** (each full-width) and the
  stacked layout then scales. The inline popover always uses side-by-side (it isn't resizable).

## Acceptance criteria
- [x] Commentary on: the summary shows two per-runner columns with names/colors and a divider; each
      column's counts reflect only that runner's seen spots.
- [x] Commentary off: unchanged single-pane summary.
- [x] Breakout window: side-by-side when wide, stacked when narrow; both scale to fit.
- [x] A spot seen by both runners appears in both columns (each column = that runner's full knowledge).

## Implementation
- `SpotSummary.compute` (TrackerCore) gains a backward-compatible `includeCell:(Int,Int)->Bool`
  filter (default: all cells). The dual view calls it twice, filtering each column to cells whose
  commentary knowledge includes that runner.
- `SpotSummaryView` gains a `Content` (`.single` / `.dual(RunnerColumn, RunnerColumn)`), a
  `dualAxis` (horizontal/vertical), a `makeContent(model:commentaryMode:)` factory, and
  `naturalWidth(for:axis:)`. Sections extracted into a reusable `sections(_:)`; runner header reuses
  the commentary hex→Color chip.
- `SpotSummaryWindowView` takes `options`, picks the axis from the available width, and scales to the
  matching natural width. `ZTrackerMacApp` passes `options` to the window; the inline popover builds
  its content via `makeContent`.

## Out of scope / decisions
- **"Collected/found" dimming stays global** (shared game truth — dungeon boxes, sword). A column
  filters *which marks a runner has seen*, not per-runner collection state (which doesn't exist in
  the model). Accepted by the user.
- Both-seen spots count in both columns (not a separate "both" bucket) — keeps the clean two-column
  mirror the user asked for.

## Tests
- `SpotSummaryTests.perRunnerFilter` — the `includeCell` filter tallies only the chosen subset
  (all / even-columns-only / none). **792 tests pass.**
