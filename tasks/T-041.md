# T-041 — "Go" button to start the run

## Description
The reference tracker starts its run timer the instant the window opens, which
is a frequent community complaint: the clock is already ticking while a player
is still loading their save and configuring the tracker.

Instead, the timer starts un-started and shows a green **Go** button in the
timer's slot. Clicking Go begins the run and swaps the button for the running
timer (main `H:MM:SS.mmm` + Pause/Reset, and the yellow groundhog lap once one
exists). Everything else — pause on Zelda rescue, groundhog lap, reset — is
unchanged and simply gated so it is a no-op before the run has started.

## Acceptance criteria
- [x] Before Go: a green "Go" button occupies the timer slot; the timer reads
      zero and does not advance.
- [x] Clicking Go starts the run **from that moment** (not from app launch) and
      replaces the button with the running timer.
- [x] `start()` is idempotent (a second Go is a no-op).
- [x] Pause/resume/togglePause are no-ops before Go; `reset()` keeps the
      started state.
- [x] Zelda-rescue pause and groundhog lap behave as before, once started.
- [x] Unit tests cover the un-started state and the Go transition.
- [x] On-device verified.
