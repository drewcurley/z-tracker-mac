# T-046.2 — Window frame off-screen orphan guard

## Description
`WindowFramePersister.restore` (T-046.1) wrote the saved frame back to the window
without checking it still intersects a connected display. The app is pinned to an
external monitor (negative-Y, next to the Windows VM); when that monitor is
disconnected or the arrangement changes, the saved frame restores off every live
screen and the window is orphaned — invisible and un-grabbable. (Surfaced during
a screen-lock episode where the external display region briefly went invalid.)

Fix: extract a pure `WindowFrameClamp` (CoreGraphics only, so it's unit-testable —
`NSRect` is `CGRect` on macOS) that checks whether the window's title-bar strip
still lands on any screen's `visibleFrame`. If not, re-home the window (keeping
its size, clamped to fit) centered on the primary screen. `restore()` now passes
the live `NSScreen.screens` visible frames through it.

## Acceptance criteria
- [x] A saved frame on a still-connected display restores unchanged.
- [x] A saved frame whose title bar lands on no connected screen is re-homed
      onto the primary (size preserved, clamped to the primary if oversized).
- [x] A title bar only slivered onto a screen (< min grab width) counts as
      orphaned and is re-homed.
- [x] Headless (no screens) skips the restore rather than forcing a bad frame.
- [x] Unit tests for the geometry; build clean; on-device restore still works.
