# T-202 — Sequoia launch crash (resource bundle Info.plist)

## Bug
An Intel tester on **macOS 15.7.4 (Sequoia)** got an immediate crash on launch:
`EXC_BAD_INSTRUCTION` in `Bundle.module` init → `fatalError("unable to find bundle")`, from
the first sprite load (`GameSprite.image` → `ItemGlyph`).

## Root cause (NOT arch-specific)
SwiftPM's resource bundle (`ZTrackerMac_ZTrackerMac.bundle`) ships as a flat folder with **no
`Info.plist`** (confirmed for *both* arm64 and x86_64 builds). macOS 26 (the dev machine)
accepts a plist-less `.bundle` in `Bundle(url:)`, but **Sequoia rejects it** — so every
`Bundle.module` candidate resolves to nil and the accessor traps. The SIGILL is just how a
Swift `fatalError` traps; it was never an ISA/Intel issue. This means the **arm64 build was
equally broken on Sequoia** — the Intel tester was simply the first person on Sequoia.

## Fix
`scripts/build-app.sh` writes a minimal, valid old-style (flattened, resources-at-root)
`Info.plist` into the resource bundle after copying it and **before** code-signing (so the
signature seals it). Resource lookup is unchanged (the bundle stays flattened; GIFs stay at
root); the plist only makes `Bundle(url:)` accept the bundle on strict OSes. `VERSION` → 0.8.2.

## Verification
Rebuilt: Info.plist present + `plutil -lint` OK, `codesign -v` OK, launches under Rosetta
with no fatalError. 730 tests pass. **Final confirmation needs the tester's Sequoia machine**
(can't reproduce Sequoia's stricter `Bundle(url:)` on the macOS-26 dev box).
