# T-070 — Persist the startup settings

## Description
Only the reminder settings persisted across launches (T-004.1); every other
startup toggle — door inference, BOARD/LEVEL, default-to-NonDescript, the
overworld/animation/broadcast options — reset each launch (user-reported for door
inference). Extends persistence to the whole startup-settings set.

- `TrackerOptions.persistedBoolKeyPaths` — the single source of truth mapping a
  stable key → each persisted Bool's storage (25 toggles). The broadcast-size
  enum and the hidden-tiles map persist under their own keys.
- `enableSettingsPersistence(store:)` loads a saved snapshot over the defaults
  (unknown/missing keys keep their default, so adding/removing a setting is safe).
- `saveSettings()` writes the current settings — called at the commit point,
  quest start, since startup settings are only editable before the run.
- `withPersistence()` (the app's new entry point) enables both reminder- and
  settings-persistence. `ContentView` calls `saveSettings()` on quest select.

## Acceptance criteria
- [x] A committed setting is restored on the next launch; untouched settings keep
      defaults; the broadcast enum + hidden-tiles map persist.
- [x] Without `saveSettings` nothing is written; a plain `TrackerOptions` (tests/
      previews) never touches `UserDefaults`.
- [x] Every persisted key path round-trips.
- [x] Unit tests (self-cleaning suites); build clean; on-device load verified.
