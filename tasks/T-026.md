# T-026 — Auto-mark always-empty overworld tiles

## Description
Each quest has overworld screens that can never contain anything (mountain /
water with no possible cave, item, or warp). The reference marks these with a
permanent **DARK_X** ("don't care") icon and makes them **non-interactive**
(`WPFUI.fs:244`, `:485` — "already set up as permanent opaque layer … nothing
else to do"). User request: auto-mark those tiles as don't-care and prevent
clicking/modifying them.

The model is already ported: `OverworldInstance.alwaysEmpty(x:y:)` (T-015.1),
backed by the reference's `owMapSquares{First,Second,Mixed}QuestAlwaysEmpty`
char grids (`OverworldData.fs:206-248`; mixed = first ∧ second). This task is
the **UI**: render + gate interaction, driven by that boolean. It is a derived
property of the quest, **not** a stored `.dontCare` mark — the grid tile stays
`.unmarked` underneath (so save/load and routing are unaffected).

## Acceptance criteria
- [x] `OverworldMapView` renders every `alwaysEmpty(column,row)` tile with a
      permanent don't-care treatment (dimmed terrain + X). On-device verified:
      X's land on exactly the mountain/water screens; terrain stays readable.
- [x] Those tiles are non-interactive: `.allowsHitTesting(false)` + a defensive
      guard in `handleLeftClick`, and excluded from the GYR highlight overlay.
      On-device: they stay plain amid the hover highlight flood.
- [x] Accessibility value reflects the always-empty state.
- [x] Tests: `OverworldInstance.alwaysEmpty` pinpoint coordinates (first-quest
      (0,0) empty, (1,0)/(7,0)/(7,7) not) added on top of the existing per-
      quest count tests.

## Out of scope
- The reference's special decorations on a few always-empty tiles — fairy
  spots (9,3),(3,4),second-quest(11,0) and the coast-item ladder box drawn on
  the map at (15,5). Deferred (follow-on); the coast box already lives in the
  item grid (T-025.1).
