# T-068 — Serial audio queue for reminders

## Description
**Bug (user-reported 2026-07-15):** clicking an item that fires more than one
audio reminder at once — e.g. getting the ladder speaks "you have the ladder"
*and* triggers a Triforce-and-Go message — plays both clips **simultaneously**,
so they overlap and are unintelligible.

Root cause: `ReminderController.handle` loops over the announcements and calls
`ReminderAudioPlayer.play` for each with no serialization
(`Sources/ZTrackerMac/ReminderView.swift:36-51`,
`Sources/ZTrackerMac/ReminderAudioPlayer.swift:16-28`). Each `play` creates a new
`AVAudioPlayer` and calls `play()` immediately; the `active` array just retains
every in-flight player, so N announcements = N overlapping voices. The live-TTS
fallback (`AVSpeechSynthesizer.speak`) queues internally, but the clip path does
not, and the two paths don't coordinate with each other either.

## Proposed approach
Give `ReminderAudioPlayer` a **serial queue**: enqueue clip keys and play the
next only when the current finishes (`AVAudioPlayerDelegate
audioPlayerDidFinishPlaying`, or chain via the clip duration). The visual path is
unaffected (toasts can stack). Consider:
- Coalescing/ordering when both a clip and a TTS-fallback announcement land in the
  same `handle` batch (single queue across both paths).
- A sensible cap / drop-oldest if a burst enqueues many clips (don't back up 10s
  of audio behind a single click).
- Preserve announcement order (ladder-have before Triforce-and-Go, per the batch).

## Acceptance criteria (draft)
- [ ] Two announcements from one action play sequentially, not overlapping.
- [ ] Order within a batch is preserved.
- [ ] Clip and TTS-fallback announcements share one queue (no cross-overlap).
- [ ] Burst handling defined (cap or drop policy) rather than unbounded backlog.
- [ ] Unit test over the queue's ordering/serialization logic.

## Notes
Depends on nothing; interacts with T-069 (if we move back to live TTS, the queue
still applies — serialize utterances the same way).

## Resolution (2026-07-16)
Resolved by the live-TTS migration (T-069): all reminders now speak through one
shared `AVSpeechSynthesizer`, which **queues utterances internally** — so a batch
from a single action (e.g. have-ladder + Triforce-and-Go) speaks sequentially
instead of overlapping. No separate serial queue was needed once the clip path
(the unserialized `AVAudioPlayer` source of the overlap) was removed.
