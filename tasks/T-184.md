# T-184 — Auto-switch the dungeon tab on marking a dungeon

## Why
"Nobody would find a dungeon and not explore it a little bit." When the user labels
an overworld tile as dungeon N, surface that dungeon's room map immediately by
switching the dungeon tab to level N.

## Scope
- Applies to the **single-tile** placement paths: click (context-menu), keyboard
  hotkey, and voice — all of which funnel through `OverworldMark.apply`'s
  `placeDungeon` closure.
- **Bulk** paths deliberately excluded: `autoMapVanillaDungeons` and the spoiler
  importer set marks straight on the grid (not via `OverworldMark.apply`), so they
  don't yank the tab around 9 times.

## Implementation
- New shared `OverworldMark.didPlaceDungeon(number, column:row:model:focus:)` that
  does both dungeon side effects together: set the location hint (existing behavior)
  **and** `focus.selectedDungeonTab = number - 1`. Replaces the triplicated hint-only
  closure at the three call sites (click / hotkey / voice), so they can't drift.

## Tests
`OverworldMarkApplyTests`: `didPlaceDungeon` switches the tab (level 6 → index 5) and
sets the hint; out-of-range levels are ignored. 710 tests pass.

## QA checklist
- [ ] Right-click an overworld tile → Dungeon → N: the dungeon panel jumps to level N.
- [ ] Same via a dungeon hotkey on the hovered tile.
- [ ] Same via voice ("<screen> level N").
- [ ] Auto-map vanilla dungeons and spoiler import do NOT thrash the tab.
