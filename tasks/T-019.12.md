# T-019.12 — Dungeon door inference

## Description
Wires the previously-dead "Do door inference" startup pref (`options.doDoorInference`,
user-reported not working). Reference behavior (`DungeonUI.fs:1148-1167`): when a
room is newly marked, if it has exactly one plausible entry — one adjacent
non-empty room whose connecting door isn't already `no` — set that door `yes`
("you must have walked in from there").

- `DungeonRoomMap.inferEntryDoor(col:row:)` — pure, unit-tested. Collects adjacent
  non-empty rooms with a non-`no` connecting door; if exactly one candidate and
  its door is `unknown`, sets it `yes`. Self-skips a Gannon/Zelda room and the
  second copy of a transport pair (teleport in, not walk).
- The room-marking paths (left-click accelerator + room-type picker + the
  VoiceOver default action, via a shared `markWithInference`) call it when the
  option is on and the room went unmarked→marked.
- `doDoorInference` plumbed `DungeonMapView → DungeonRoomGridView → RoomCellView`.

## Acceptance criteria
- [x] One adjacent marked room (door unknown) → that door inferred `yes`.
- [x] Zero / ≥2 candidates → no inference; a `no` door isn't a candidate.
- [x] A single candidate door that's already set (not unknown) is preserved.
- [x] Gannon/Zelda + second-transport rooms don't infer; off-map neighbor invalid.
- [x] Gated by `doDoorInference`; fires on both left-click and picker marking.
- [x] Unit tests for all branches; build clean.
- [ ] End-to-end confirmed by the user (enable pref → mark a room by a marked
      neighbor → door greens).
