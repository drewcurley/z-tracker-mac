# T-016.2 — HDN basement-stair metadata

## Description
Ports `StairKind`/`BoxOwner` (`TrackerModel.fs:587-597`) and
`Box.CurrentlyHasBasementStair` (`:607-632`, ~26 lines) — which dungeon-room-
grid cell a box's stair icon renders in, keyed on quest + dungeon-label-char +
box index (vanilla dungeon-shape knowledge). Applies in both DEFAULT and HDN
but is most load-bearing for HDN letter-based identification.

## Acceptance criteria
- [x] `StairKind` (`never/always/likeL2/likeL3`) + `BoxOwner`
      (`dungeonIndexAndNth/dungeon1or4/none`) ported and attached to `Box`
      (defaulted so existing `Box()` call sites are unaffected); DEFAULT
      box-construction StairKind table (`TrackerModel.fs:742-753`)
      transcribed.
- [x] `currentlyHasBasementStair` ported (both DEFAULT and HDN branches) —
      computed on `DungeonTrackerInstance` (which has the kind/quest/label
      context the HDN branch needs) rather than on `Box`. 4 tests pin it
      against the reference's quest/label/box-index table, both quests, both
      modes.

## Out of scope
- The dungeon-room-grid UI that renders the stair — deferred until that UI
  exists (this task ports the metadata that feeds it). **Unconsumed model**
  until then; ported for 1:1 completeness.

## Risks / dependencies
- Depends on T-016.1. Re-adds the `StairKind`/`BoxOwner` constructor args to
  `Box` that T-013 deliberately deferred.
