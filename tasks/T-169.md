# T-169 — Per-context hotkey "smarts"

## Description
Second of the hotkey PRs (after T-168 contexts). Adds the per-context repeat-press
behaviors from `extras.md` §hotkeys and the v1.3 Unmark–Remark chains from `whats-new.md`.

- **Item boxes**: a repeat of the held item cycles possession green→skip→red→green. A
  *fresh* mark stays YES (this clone's choice, user-confirmed 2026-07-22, vs the
  reference's NO). The `Nothing` key clears a filled box, then toggles the empty outline.
- **Overworld shops**: a shop key on a tile that's already a shop removes that item, adds
  a new one to the free slot, or (both slots full) replaces the primary and keeps the
  secondary.
- **Overworld brightness**: a repeat of a bright/dark-toggleable mark flips its used state.
- **Blockers**: a repeat of the box's kind clears it to empty.
- **Dungeon rooms**: a repeat toggles the mark off; and an Unmark→Remark of the same room
  with the same key fires the linked action — triforce/map toggles, moats→maybe-Ladder,
  meat→Bait, life-or-money→Money, Gohma→Bow, Digdogger→Recorder, Dodongo→Bomb, Heart, and
  (adapting the reference's mouse-warp to our no-warp model) OtherKeyItem / ItemBasement
  park the dungeon-item cursor on the target box.

The maybe-blocker logic follows the reference: promote a maybe to full, else add a maybe,
else nothing; skips dungeon 9 and a blocker whose unblocker the player already holds.

## Acceptance criteria
- [x] Item-box possession cycle; fresh press stays YES.
- [x] Shop add / remove / replace on an existing shop.
- [x] Overworld brightness repeat-toggle; blocker + room repeat-unmark.
- [x] Full 11-row Unmark–Remark table, scoped by tab so an identical room in another
      dungeon can't false-fire; successive chains fire each time.
