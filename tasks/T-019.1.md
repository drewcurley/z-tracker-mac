# T-019.1 — Dungeon band: Notes + keyboard-focus fix

## Description
First slice of the **dungeon tracker** (middle band), built frame-first per the
scoping plan (`docs/design/dungeon-tracker.md`). Adds the reference's single
global **Notes** box (`WPFUI.fs:1219-1229`) below the overworld map, and fixes a
foundational **keyboard-focus bug** that surfaced while testing it.

- **Notes (TrackerCore + UI):** `TrackerModel.notes: String` — free-text scratch
  space; player *knowledge*, so a groundhog reset keeps it (like `levelHints`).
  `NotesView` is a `TextEditor` (lime-on-dark, nodding at the reference) with a
  placeholder, in a "Notes" section below the recorder-destination bar. The
  room-map grid + blockers land above it in later slices.
- **Keyboard-focus fix (T-019.1):** an unbundled SwiftPM executable launches with
  an accessory activation policy — windows show and take mouse clicks, but the
  app never becomes the *key* window, so text fields blinked a caret while
  keystrokes went to the previously-active app. Added an `AppDelegate` that sets
  `NSApp.setActivationPolicy(.regular)` + activates on launch. This is
  foundational for Notes now and hotkeys later.

## Acceptance criteria
- [x] `TrackerModel.notes` defaults empty; survives a groundhog reset

- [x] Notes box renders in the band below the map with a placeholder; typing

- [x] The app takes keyboard focus (was the blocker) — verified by the user
      typing into Notes.
- [x] Build clean (debug + release); full suite passes.
