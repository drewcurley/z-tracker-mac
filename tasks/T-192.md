# T-192 — Timer voice control + crash-recovery resume

## Ask (user requests)
1. Voice commands to **start** and **pause** the run timer.
2. Voice-marking a room **non-descript** should default it to the cleared/completed state.
3. Reopening a saved session should **resume the timer by default** (crash recovery — the
   user recovered an autosave after a crash but forgot to restart the timer).
4. A persistent setting: on reopen, the timer either **continues where it left off** (active
   time) or counts **real time since the run began** (including the closed gap).
5. When a previous session exists, **auto-open it after 5 seconds** on launch.

## Implementation
- **Voice** (TrackerCore + VoiceController): `VoiceCommand.startTimer` / `.pauseTimer`;
  `Timer_Start` / `Timer_Pause` catalog actions ("start/resume timer", "pause/stop timer").
  Two-word phrases beat the bare "start" nav phrase via longest-match. `VoiceController`
  gains the `timer` and dispatches: start → `start()` before Go, else `resume()`; pause →
  `pause()`. Non-descript room set by voice also marks the room completed.
- **Timer** (`TrackerTimer`): stores `runStart` (wall-clock first Go), persisted in `State`.
  `restore(_:resuming:realTimeSinceStart:asOf:)` resumes by default and picks the elapsed
  basis (active saved elapsed vs `now − runStart`).
- **Restore** (`GameSave.apply`): resumes and honors the mode from `options`.
- **Setting** (`TrackerOptions.timerRealTimeSinceStart`, default **true**): persists
  immediately (like the theme); Settings shows it as a two-option radio group (real-time on
  top). Real-time falls back to active elapsed for legacy saves with no `runStart`.
- **Auto-open** (`ResumeSessionPrompt`): replaces the resume confirmationDialog with a
  custom overlay that counts down 5s and auto-resumes; hovering the card or pressing any
  button cancels the countdown.

## Tests
`VoiceGrammarTests`: timer phrases parse (and don't hijack the "start" nav phrase).
`GameSaveTests`: reopen auto-resumes; real-time vs active elapsed math. 724 tests pass;
auto-open + resume QA'd on device (user sign-off).

## Note
Real-time is the default per the user's request; a normal quit-and-reopen therefore adds the
closed-app gap to the clock (surfaced to the user).
