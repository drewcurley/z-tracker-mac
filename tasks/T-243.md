# T-243 — Security hygiene

## Problems (audit)
- The voice pipeline appended every utterance (and the live heard text every second) to a fixed,
  world-readable `/tmp/ztracker-voice.log`, always on, unbounded, on the main thread, following
  symlinks — a privacy leak for streamers and a symlink-redirect risk on shared Macs.
- The update banner opened the GitHub API's `html_url` unvalidated.
- Saving the render-perf log deleted the destination before copying (a failed copy lost the file).
- `Package.resolved` was git-ignored and the Sparkle floor (`from: "2.6.0"`) admitted versions with
  known high-severity advisories; compiler intermediates (`HotkeyEditorView-2.*`, exposing local
  paths) were committed; `.gitignore` didn't block signing/update-key material.

## Fix
- `VoiceDebugLog`: off unless `defaults write com.drewcurley.ztracker-mac ZTrackerVoiceDebugLog -bool YES`;
  writes `~/Library/Logs/ZTracker/voice.log` (dir 0700, file 0600, `O_NOFOLLOW`, capped at 1 MB).
- `UpdateChecker.trustedReleaseURL`: only `https://github.com/drewcurley/z-tracker-mac/…`.
- PerfLog save: copy to a same-volume temp, then `replaceItemAt`.
- `Package.resolved` committed (Sparkle 2.9.6, patched); floor raised to `from: "2.9.6"`;
  artifacts removed; `.gitignore` blocks `*.p12 *.p8 *.key *.pem *.cer *.csr sparkle_private_key*`
  and compiler intermediates.

## Not done here (owner actions — outside the repo)
- Secure `~/Documents/ztracker-signing/` (unencrypted `developer_id.key`, plaintext app-specific
  password RTF), back up the Sparkle EdDSA key, rotate the app-specific password.
