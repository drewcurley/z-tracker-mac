# T-018.2 — Reminder/announcement engine

## Description
Ports the edge-triggered half of `allUIEventingLogic` (`TrackerModel.fs:1568-
1750`) + its transition trackers (`:1509-1530`) +
`ResetForGroundhogOrRoutersOrFourPlusFourEtc` (`:1531-1552`) as a
`ReminderEngine` whose `poll(...) -> [ReminderAnnouncement]` the app calls on
its timer.

**Architecture decision (the one T-018 flagged), resolved by consulting the
source + this project's established pattern:** `ITrackerEvents`' *state-push*
callbacks (`CurrentHearts`, `DungeonLocation`, `RoutingInfo`,
`CompletedDungeons`, …) are redundant under `@Observable` — the views read the
model directly — so they are not ported as callbacks. Only the *edge-
triggered announcements* are stateful logic; those are the engine. A literal
delegate-protocol port was considered and rejected (it would re-add the
redundant state-push surface).

## Acceptance criteria
- [x] Architecture decided (reactive poll → announcements, not a literal
      delegate) and documented in the type.
- [x] `ReminderAnnouncement` (8 cases) + `ReminderEngine.poll` porting the

      non-resets).
- [x] 14 tests covering each announcement type, the TAG-103 suppression gate,
      hardCanonical maybe-blocker matching, completed-dungeon exclusion, and
