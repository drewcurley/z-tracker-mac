# T-112 — Consistent dungeon naming

## Description
The dungeon naming was inconsistent across the app. Now the overworld picker's
dungeon menu, the dungeon-map title, and the dungeon voice/toast reminders all
reflect the user's scheme, matching the reference:

- **Picker menu + map title** use the column word — LEVEL or BOARD
  (`BOARDInsteadOfLEVEL`) — joined to the slot label: `LEVEL-9`, `BOARD-3`, or
  `LEVEL-A`…`H` under Hidden Dungeon Numbers. Centralized in
  `DungeonLabeling.columnName` so both agree (previously the menu said
  "Dungeon A" / "Level 9" and ignored BOARD).
- **Voice/toast** keep the word "Dungeon" (the reference does *not* use LEVEL/BOARD
  here) but use letters under HDN: a **completed** dungeon uses its *assigned*
  label (`GetDungeon(i).LabelChar`, or "This dungeon is complete" when unknown,
  `UI.fs:1442-1449`); a **revisit** reminder uses the *slot* letter `'A'+d`
  (`UI.fs:1508-1512`). These two intentionally differ, per the reference.

## Acceptance criteria
- [x] Picker dungeon menu shows LEVEL-/BOARD- + slot label (letters under HDN).
- [x] Dungeon-map title shares the same helper.
- [x] Completed-dungeon voice uses the assigned HDN label / "This dungeon" fallback.
- [x] Revisit voice uses the slot letter under HDN.
- [x] Unit-tested; build + full suite clean.
