# T-043 — Top-section regrouping + reflow

## Description
The upper area had grown into one wide `HStack(DungeonTrackerView,
ItemProgressGridView)`, with items, seed flags, and status readouts all crammed
into a single grid view. Per the user, the top section has four logical areas:

1. **Dungeons** — location, triforce, item boxes.
2. **Items** — white-sword item, armos, coast picker boxes + other
   obtainable-item toggles + take-any hearts + the sword-cave hints.
3. **Flags** — swordless (WSMS→bomb-upgrade), Book vs Shield. (Book-as-atlas and
   mirror-overworld are named in the reference but not yet modeled — left out;
   no invented flags.)
4. **Info** — OW spots left, gettable, Max Hearts, the map-overlay toggles, and
   the groundhog reset.

These are now four titled group cards laid out left-to-right in a custom
`FlowLayout` that reflows to new rows when the window is too narrow.

## Acceptance criteria
- [x] Four titled groups: Dungeons · Items · Flags · Info.
- [x] Laid out left-to-right when wide; wrap to new rows when narrowed.
- [x] `ItemProgressGridView` split into `ObtainableItemsView` / `SeedFlagsView` /
      `MapInfoView`; behavior (toggles, pickers, hints, overlays, reset) intact.
- [x] Reflow logic (`FlowPacking`) unit-tested.
- [x] On-device verified: all four in one row at 1200; Flags+Info wrap below at
      760.
