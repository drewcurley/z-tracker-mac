# T-021 — Dungeon item-tracker view

## Description
The first visible piece of the main-tracker UI epic: renders the T-013/T-016
dungeon model with the T-020 sprites. Nine dungeon cards, each with its
located triforce numeral + triforce pip and its item boxes; left-clicking a
box opens an item picker (Have it / Don't want it / Don't have it / Clear =
`Box.playerHas` YES/SKIPPED/NO + `cellCurrent`), matching the reference's box
popup. Basement-stair glyphs render `currentlyHasBasementStair` (T-016.2), and
a card highlights green when the dungeon `isComplete`. The three standalone
boxes (Coast/Armos/WS-cave) are shown too.

Per the project's **aesthetic license**, the reference's cramped grid is
re-laid-out as clean cards, keeping the recognizable Zelda item sprites.
Replaces the T-012 debug panel's role as the main surface (the debug toggles
remain in a collapsed disclosure).

## Acceptance criteria
- [x] Nine dungeon cards render the model's boxes with real item sprites,

## Verification (visual, against the running app)
Launched, selected First Quest, confirmed: 9 cards with the correct box
layout + basement stairs; opened a box picker (real sprites, black→transparent
correct); set D1 box 1 = Ladder → box showed the ladder sprite with a green
"have it" border **and** the live reminder toast "Don't forget that you have
the ladder" fired (box → `PlayerComputedStateSummary.haveLadder` → reminder
engine → toast — the full pipeline, live). Screenshots archived.
