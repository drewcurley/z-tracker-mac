# T-015.5 — Any-road warp destination wiring

## Description
**Narrowed from the original "live placeholder wiring" scope after a grounding
read.** The original bundle (mirror + recorder-warp + any-road) mixed one
clean, ready piece with two entangled ones:

- **Any-road destinations — done here.** `OverworldMapView` fed
  `dynamicGraph(anyRoads: [])`. Now wired to live
  `mapState.anyRoadLocations` (the marked any-road screens, from T-015.3), so
  two-or-more marked any-roads warp between each other (cost 4) in the hover
  routing graph. The graph machinery already existed (T-010); it was just
  being fed empty.
- **Recorder-warp destinations — deferred.** The reference derives these in
  the reminders/orchestration path (`recomputeMinimumFutureItemProgression`
  → `RoutingInfo` → `OverworldRouting.repopulate`, `TrackerModel.fs:1607`),
  which needs the recorder-warp *options* (`recorderToNewDungeons`/
  `recorderToUnbeatenDungeons`), HDN triforce-index logic, and
  `vanilla1QDungeonLocations` — none ported. Folds into **T-018**.
- **`MirrorOverworld` — split to T-015.7.** It's a full display-flip feature
  (flips the whole map's marks + background, `Z1R_Avalonia/UI.fs:1302`), not
  just a routing flag; deserves its own task.
- **Warp-line dashed/skipped styling — deferred** with the warp features: it
  needs warp-vs-walk edge metadata on `OverworldRouteLineSegment` that the
  graph doesn't yet carry.

## Acceptance criteria
- [x] `OverworldMapView` feeds live `mapState.anyRoadLocations` to
      `dynamicGraph(anyRoads:)`, replacing the empty placeholder.
- [x] Test that any-road marks populate `anyRoadLocations` by warp number and
      that the view's extraction produces the routing input.

## Out of scope (split into follow-ons)
- `MirrorOverworld` display + routing — **T-015.7**.
- Recorder-warp destinations — **T-018** (reminders/orchestration).
- Warp-line dashed/skipped styling — deferred with the above.

## Risks / dependencies

  already ported and tested in T-010.
