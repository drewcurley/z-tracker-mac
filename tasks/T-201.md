# T-201 — Dual-architecture builds (Apple Silicon + Intel)

## Ask
Support Intel Macs. The user wants a **dedicated native binary per arch** (not a universal
binary) — a native arm64 build and a separate native x86_64 build — and every release should
produce both.

## Findings
The app was already architecture-clean: zero arch-specific code, no binary/xcframework
dependencies, and every framework used (SwiftUI/AppKit/Speech/AVFoundation/CoreGraphics/…)
exists on Intel. It was arm64-only purely because the build compiled a single host-arch
binary. Floor stays macOS 14 (Sonoma) — the app uses `@Observable` (Observation, 14+) in 26
files — which Intel Macs from ~2018 run, so no refactor needed.

## Change
- `scripts/build-app.sh` takes an arch arg (`arm64` | `x86_64`, default host) and passes
  `--arch` to `swift build` + `--show-bin-path`. Each build is a native single-arch binary.
- `scripts/make-dmg.sh` builds **both** arches by default into labeled images:
  `ZTrackerMac-<ver>-AppleSilicon.dmg` and `-Intel.dmg` (pass an arch to build just one).
  Notarization loop is per-DMG.
- README requirements/install updated (pick your download by chip); `docs/RELEASING.md`
  updated for the two-DMG flow. `VERSION` → `0.8.1`.

## Verification
`swift build -c release --arch x86_64` compiles clean and produces an x86_64 binary
(verified on the Apple-Silicon dev machine). Runtime testing of the Intel slice needs real
Intel hardware (a user tester will validate). 730 tests pass (unchanged; build-only change).
