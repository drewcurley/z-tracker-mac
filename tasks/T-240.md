# T-240 — Timer restore correctness — exclude pauses, keep paused/lap state, no stale auto-resume

## Problems (audit)
- **High** — real-time restore (the default) added every in-session pause plus downtime; a run saved
  while paused came back *running*; a days-old save auto-resumed and restarted its clock; the
  setting text understated what it did. The lap and running/paused state weren't saved at all.

## Fix
- The timer tracks time spent paused; `State` gains optional `wasRunning`, `pausedTotal`,
  `lapOrigin`, `hasLap` (older saves still decode). `restoredElapsed` (pure): real-time mode adds the
  closed gap only for a run that was running, never pauses, never less than the saved elapsed.
- A run saved paused reopens paused; the lap is restored; the wall-clock anchor is re-based on
  restore so repeated crashes stay consistent.
- Sessions older than 6 h don't auto-resume (the prompt waits for a choice); setting text corrected.
- Behavior change vs T-192: a run saved *paused* no longer auto-starts on reopen (T-192's goal —
  "a crash mid-run shouldn't leave the timer paused" — is preserved exactly).
