# T-167 — Custom overworld map with fog-of-war

## Description
Import a custom overworld map image (e.g. from the Infinite Hyrule generator) and run a
seed against it with every screen hidden until you mark it. The vanilla map's fixed truth
— dead spots, fairy fountains, GYR/routing — is map-specific and therefore meaningless on
a custom map, so all of it is turned off; fairy fountains become hand-placed instead.

Entry point is on the startup screen ("Start: with a custom overworld map…", below the
saved-state button), matching the reference's ⋯ affordance next to "Start: First Quest
Overworld".

### Quest semantics (corrected during review)
All four overworld types share the same vanilla map; the type selects (a) which cave /
burn-bush / push-block / recorder openings exist and (b) which secrets & door-repair rules
apply. Mixed-First/Mixed-Second use openings from both quests with first-/second-quest
rules respectively. On a custom map the openings are unknowable, so the chosen type drives
only the secrets/door-repair logic.

### Rendering
The map is drawn as **one image stretched across the whole 16×8 grid**, not 128 per-screen
crops. Slicing required the source to be an exact multiple of 16×8 NES screens: integer
`width / 16` dropped the remainder so every column drifted, and each crop was then
aspect-fill-cropped inside its tile, which zoomed and clipped imported maps. Stretching
maps screen N onto cell N for any resolution or aspect. Fog is a cheap gradient cover
(no per-tile bitmaps) so 128 covers cost no framerate.

## Acceptance criteria
- [x] Import a map image and start a run against it; screens begin fogged.
- [x] Setup dialog offers all four overworld types, defaulting to First Quest. (Uses a
      `.sheet` — macOS alert-backed `confirmationDialog` silently drops buttons past ~3,
      which had hidden Mixed-Second.)
- [x] Marking a screen reveals it; clearing a mark does not re-hide; manual reveal/re-hide
      available from the context menu.
- [x] No dead spots — every screen is markable from click, hover, voice, and hotkeys
      (single source of truth: `TrackerModel.isDeadSpot`).
- [x] Vanilla fairy spots, GYR highlight, and route lines suppressed; fairy fountains
      placeable by hand from the tile menu (grouped with the other marks, under Potion
      shop). Placing one reveals its screen, like any mark.
- [x] "OW spots left" counts every screen; "gettable" is hidden (it depends on terrain the
      tracker can't know).
- [x] Map path + reveal state + placed fairies survive save/load.
- [x] Pre-T-167 saves still decode (new fields optional — synthesized `Decodable` does not
      apply property defaults for missing keys).
