# T-014 — Player state: PlayerComputedStateSummary derivation

## Description
The central "derived player state" object — a pure recomputation over
`T-012`'s two data bags and `T-013`'s `AllBoxes()`, grounded in
`TrackerModel.fs:841-958` (~120 lines): type at `:841-861`, recompute
function `recomputePlayerStateSummary()` at `:865-958`.

16 fields (`HaveRecorder`, `HaveLadder`, `HaveAnyKey`, `HaveCoastItem`,
`HaveWhiteSwordItem`, `HavePowerBracelet`, `HaveRaft`, `PlayerHearts`,
`SwordLevel` 0-3, `CandleLevel` 0-2, `RingLevel` 0-2, `HaveBow`,
`ArrowLevel` 0-2, `HaveWand`, `HaveBookOrShield`, `BoomerangLevel` 0-2),
each derived by iterating `AllBoxes()` for `PlayerHas.YES` cells matching
specific `ITEMS.*` constants, then layering in `T-012`'s progress/starting
flags, then the two standalone box "done" checks
(`ladderBox`→`HaveCoastItem`, `sword2Box`→`HaveWhiteSwordItem`).

Also needs the three global option flags this derivation branches on
(`TrackerModel.fs:155-176`): `IsCurrentlyBook` (Book vs. Shield naming),
`IsBookAnAtlas` (Book grants dungeon-map-reveal), `IsWSMSReplacedByBU`
(White-Sword/Magical-Sword boxes replaced by Bomb Upgrade in some seed
variants — changes sword-level computation).

## Acceptance criteria
- [ ] `PlayerComputedStateSummary` ported with all 16 fields.
- [ ] Recompute logic ported faithfully from `:865-958`, including the
      three-flag branching (book/atlas/WSMS-as-BU) — port structure, don't
      simplify the branching, per the same discipline used for
      `findAllBestPaths` in `T-010`.
- [ ] Tests: hand-constructed scenarios (specific boxes marked done with
      specific items, specific starting items, specific progress flags →
      exact expected `PlayerComputedStateSummary`) — known-scenario
      regression tests, not just "it computes something."
- [ ] `T-011`'s placeholder `ladder`/`raft` constants in `OverworldMapView`
      replaced with `playerComputedStateSummary.HaveLadder`/`.HaveRaft`.

## Out of scope
- The `playerHasAtlas`/atlas-changed event cascade's UI consumption
  (dungeon-map-reveal display) — a later dungeon-tracker-UI task, not this
  one (this task only needs the boolean's correct *value*, not everywhere
  it's displayed).
- Shop/cave discovery flags and the overworld `MapStateSummary` recompute
  that consumes this — `T-015`.

## Risks / dependencies
- Depends on `T-012` and `T-013` — both must exist first; this task is
  pure glue/derivation over them, not independently buildable.
