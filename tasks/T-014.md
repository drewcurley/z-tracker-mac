# T-014 — Player state: PlayerComputedStateSummary derivation

## Description
The central "derived player state" object — a pure recomputation over
`T-012`'s two data bags and `T-013`'s `AllBoxes()`, grounded in
`TrackerModel.fs:841-958` (~120 lines): type at `:841-861`, recompute
function `recomputePlayerStateSummary()` at `:865-958`.

16 fields (`HaveRecorder`, `HaveLadder`, `HaveAnyKey`, `HaveCoastItem`,
`HaveWhiteSwordItem`, `HavePowerBracelet`, `HaveRaft`, `PlayerHearts`,
`SwordLevel` 0-3, `CandleLevel` 0-2, `RingLevel` 0-2, `HaveBow`,
`ArrowLevel` 0-2, `HaveWand`, `HaveBookOrShield`, `BoomerangLevel` 0-2),
each derived by iterating `AllBoxes()` for `PlayerHas.YES` cells matching
specific `ITEMS.*` constants, then layering in `T-012`'s progress/starting
flags, then the two standalone box "done" checks
(`ladderBox`→`HaveCoastItem`, `sword2Box`→`HaveWhiteSwordItem`).

Also needs the three global option flags this derivation branches on
(`TrackerModel.fs:155-176`): `IsCurrentlyBook` (Book vs. Shield naming),
`IsBookAnAtlas` (Book grants dungeon-map-reveal), `IsWSMSReplacedByBU`
(White-Sword/Magical-Sword boxes replaced by Bomb Upgrade in some seed
variants — changes sword-level computation).
