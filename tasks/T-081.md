# T-081 — Recorder destination in the Info area

## Description
The recorder destination used a full-width bar between the overworld and dungeon
maps. Move it into the **Info** group, below the six overlay-toggle icons, as a
compact widget, and change its logic per the user (2026-07-16):

- Representation: `◄ [recorder] ► N  coord`.
- Destinations are a function of which **triforces you hold**, NOT of whether the
  dungeon is placed on the overworld map. A held-triforce dungeon is a valid
  destination even when unplaced; its coordinate simply shows `—` until marked.
  (New `RecorderDestinations.infoEntries` — the map-highlight `compute`, which
  faithfully drops unplaced dungeons per the reference, is unchanged.)
- The recorder icon is darkened until you have the recorder; the number is `0`.
- There is **no default destination**: with the recorder but no triforce yet the
  number stays `0` (you don't know which dungeon the recorder came out of until
  you've beaten one). Once a triforce is obtained it shows the lowest
  obtained-triforce dungeon — unless the arrows have been used, which pins the
  choice (`recorderDestinationManual`).
- The overworld diamond marker follows the same selection so map + widget agree.

## Acceptance criteria
- [x] Widget lives in the Info group below the six overlay icons; old bar removed.
- [x] Destinations driven by held triforces, independent of overworld placement.
- [x] Darkened recorder + `0` with no recorder; `0` (no default) with recorder/no triforce.
- [x] Lowest-triforce default; arrows pin a manual choice.
- [x] Map diamond marker matches the widget's selection.
- [x] Unit tests for `infoEntries` (lists unplaced) + `selectedEntry` (auto/manual/wrap).
- [x] Build clean; on-device render verified (no-recorder → darkened + 0).
