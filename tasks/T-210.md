# T-210 — Timeline always fills the width

## Problem
T-209 fit long runs to the pane but **capped** the scale at 26 px/min, so a short/new run only
used a fraction of the width — a 10-minute axis occupied ~a quarter of the window with the rest
empty.

## Fix (`GameTimelineView`)
- Removed the `idealPxPerMinute` cap and the `minPxPerMinute` floor. `pxPerMinute` is now purely
  `(paneWidth - rightMargin) / (maxMinute + 1)`, so the **whole run always fills the pane** at
  every length: a new run spans the full width, and each pixel represents more time as the run
  grows (time-compressed, entire duration always in view, never scrolls).
- `contentWidth` is just the pane width now (content always fits). Adaptive axis step and
  proximity icon-stacking (T-209) still keep it legible as it compresses.

## Acceptance criteria
- [x] A brand-new (~10-min) run fills the whole pane width.
- [x] As the run grows, the axis stays full-width and each pixel represents more time.
- [x] Rescales live on window resize; never scrolls.
