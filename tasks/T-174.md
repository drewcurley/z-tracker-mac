# T-174 — Distribution + check-on-launch update notice

## Description
Make the app distributable and let users learn when a newer version exists, on the free
path (GitHub Releases, no Apple Developer account) while staying a drop-in away from
notarization + Sparkle later.

- **Update notice:** on the startup screen, one unauthenticated GET to the project's
  GitHub `releases/latest`, compared to `CFBundleShortVersionString`; a strictly-newer
  release shows a dismissible banner with a Download link to the release page. Gated on a
  durable **"Check for updates on launch"** setting (Settings → Other, default on). Sends
  no data; fails silently offline; never auto-installs.
- **DMG packaging:** `scripts/make-dmg.sh` builds a drag-to-install `.dmg` with an
  Applications symlink; optionally notarizes + staples when a notary profile is supplied.
- **Notarization-ready signing:** `build-app.sh` already env-gates the signing identity;
  now, when that identity is a "Developer ID Application", it signs with the hardened
  runtime + `Bundle/ZTrackerMac.entitlements` (audio-input for voice). The default
  self-signed dev path is unchanged.
- **Docs:** `docs/RELEASING.md` — cutting a release, the Gatekeeper bypass for unsigned
  installs, and the notarization + Sparkle path.

## Acceptance criteria
- [x] Version comparison handles v-prefix, short forms, pre-release suffixes, and garbage
      (never nags on unparseable input). Unit-tested.
- [x] Update check is gated on the setting, off-by-a-toggle, and sends no data.
- [x] `make-dmg.sh` produces a working `.dmg` (verified: 5.1 MB UDZO at v0.8.0).
- [x] Developer ID builds get hardened runtime + entitlements automatically; dev builds
      unchanged.
- [x] RELEASING.md documents the free path now and the notarized/Sparkle path later.

## Out of scope (deliberate, per user "not sure yet on Apple Developer account")
- Actually enrolling / notarizing — the scripts are ready; running them needs the account.
- Sparkle auto-install — documented as the drop-in next step.
