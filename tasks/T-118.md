# T-118 — QA round-2 fixes

Five fixes from a QA pass on the running build.

## 1. Spot Summary reflects the letter's taken state
The letter was force-marked *used* on placement (`placesUsedWhenMarked`), which set
its `extraData` to the delivered value — so `havePotionLetter` read false right after
finding it, and the summary state was inverted. Now:
- The letter is **not** force-used on placement (`extraData == 0` → `havePotionLetter`
  true; you hold the potion letter).
- Its map dim is **inverted** (dark while held, bright once delivered/used), matching
  the reference letter tile.
- The Spot Summary treats the letter as **taken once found** (its map toggle is a
  *delivered* flag, not a summary state).

## 2. Finish time posted to Notes includes milliseconds
`Finished in H:MM:SS.mmm` (via `TimerFormatting.hmsMillis`) so close race ties are
visible.

## 3. Marking the wood-sword cave "used" grants the wood sword
Toggling the wood-sword cave (`swordCave(1)`) used/unused now sets/clears
`playerProgress.hasWoodSword` — the cave is where the wood sword is collected.

## 4. Timeline hovers show the split
The `.help` tooltip was applied *after* `.position`, which expands each item's frame
to fill the whole timeline — so every tooltip overlapped and none tracked its icon.
Moved `.help` onto the sized icon before `.position`.

## 5. Overworld enemy sprites stack vertically along the left
Changed from a bottom-edge `HStack` to a left-edge `VStack` so the enemies don't
cover the tile's own mark icon.

## Acceptance criteria
- [x] Letter shows as taken in the summary once found; `havePotionLetter` correct.
- [x] Finish time in Notes includes ms.
- [x] Wood-sword cave used ⇄ `hasWoodSword`.
- [x] Timeline hover shows "split  name — location" tracking each icon.
- [x] Overworld enemies stack vertically, clear of the mark icon.
- [x] Unit-tested where logic changed; build + full suite clean.
