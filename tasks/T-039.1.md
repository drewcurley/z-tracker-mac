# T-039.1 — Hint Decoder

## Description
The consolidated **Hint Decoder** popover (INFO group), ported from
`MakeHintDecoderUI` (`Z1R_WPF/UIComponents.fs:629-796`). It does the job the
per-target `HintLabel` pickers (T-039) can't: it **translates the opaque
in-game hint phrase** to what it points at, so a player who sees "Aquamentus
Awaits" or "Meet the old man at…" knows it means Level 1 / the Magical Sword.

- **Model (TrackerCore):** `HintPhrases` — the phrase→meaning table
  (`OverworldData.hintMeanings`, verbatim strings) plus the "Other hints" list
  (`UIComponents.fs:762-790`). `LevelHintPhrase { phrase, meaning, target }`.
  `HintZone.forZoneChar` (inverse of `zoneChar`) so a placed dungeon can
  auto-set its region hint.
- **UI:** `HintDecoderView` — an 11-row grid of `phrase → meaning → region
  picker` (the picker reuses `HintLabel`, writing the same `levelHints` the
  dungeon cards / sword boxes read, so all stay in sync), and an "Other hints"
  disclosure listing the 7 informational hints.
- **Dungeon → hint sync (user request):** placing a dungeon marker on the
  overworld auto-sets that dungeon's location hint to the screen's region
  (`OverworldMapView.onPlaceDungeon` → `HintZone.forZoneChar(OverworldZones…)`).

The two sword rows decode to the **item** an NPC gives — "(npc) has (item) at"
is the **White Sword item** (the random item in that cave, not the White Sword
weapon), "Meet (npc) at" is the **Magical Sword** (per the user, and the
reference's meanings).

## Out of scope
- **Auto-darkening the map** for "No feat of strength" / "Sail not" (the
  reference offered these as spot-darkening checkboxes). Per the user, these
  hints are informational only — a hinted feat/raft spot may still hold a useful
  (just non-critical) item, so darkening would hide real value. Listed as text.
- The halo-on-triforce hover that shows possible locations (a separate reference
  feature; the region picker already records the hint).
