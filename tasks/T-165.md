# T-165 — Save/Load UI (Phase 2)

## Description
The user-facing half of Save/Load, on top of the T-164 serialization core (audit #4).

- `GameSave` service: combines `TrackerModel.State` + `TrackerTimer.State` into one
  versioned `SaveFile` (JSON), owns the on-disk layout in `~/Documents/ztracker/`, and
  provides encode/write/read/apply plus autosave/clear/pendingResume.
- **Save… / Load… buttons** under the Reset buttons. Save → timestamped file via
  `NSSavePanel` (default `~/Documents/ztracker/`); Load → `NSOpenPanel`, confirming
  before it replaces an active run.
- **Autosave** (`last-session.json`) every ~60s while a run is active and unfinished —
  the resume source + crash backstop.
- **Startup resume** — a SwiftUI `.confirmationDialog` (not a raw `NSAlert`, which
  doesn't display from `.onAppear` at launch): "Resume your last run?" restores state
  with the timer **paused** at its saved elapsed. Discard forgets the session.
- **Quit dialog** — folded into `AppDelegate.confirmQuit`: an unfinished run gets the
  standard **Save / Don't Save / Cancel** (Save flushes the session, Don't Save discards
  it, Cancel aborts the quit). Supersedes the plain timer-running warning. A finished
  run (Zelda rescued) never prompts and clears the session.

## Notes
- The resume prompt was initially an `NSAlert` from `.onAppear` and silently didn't
  display (app not active/key yet at launch); fixed by making it a state-driven SwiftUI
  dialog. Live-QA'd: quit→Save→relaunch→Resume restores marks + paused timer.
- Reset dialogs' stale "(no save yet)" copy updated to "Use Save first…".
