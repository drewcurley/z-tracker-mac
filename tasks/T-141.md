# T-141 — Voice: second shop item

## Description
Fixes a reported voice bug: saying a second shop name on a tile that's already a shop
**overwrote** the primary instead of setting the tile's **second** item (T-060).

- `OverworldMark.applyVoiceSecondShopItem(_:column:row:grid:)` — pure, testable: if the
  mark is `.shop(new)` and the tile is already `.shop(first)` with `new != first`, it
  sets the second item and returns `true` (caller stops); otherwise `false` (apply the
  mark normally). You can't say "2nd item" by voice, so the additive reading is what's
  meant.
- `VoiceController` consults it before the normal overworld apply.

## Acceptance criteria
- [x] "bomb shop" then "candle shop" on one tile → primary bomb kept, second = candle.
- [x] Empty tile / same kind / non-shop mark → not handled (normal apply proceeds).
- [x] 570 tests pass.

## Out of scope (needs a design decision — see below)
Items-region voice: **progression toggles** ("take wood sword", "bombs", "meat", "ganon")
and the **coast / armos / white-sword item boxes**. Open questions: are progression
toggles *global* (work in any region) or region-scoped? Word collisions with existing
overworld shop marks ("meat" shop vs "meat" bait; "wood sword" cave vs wood-sword flag).
The item boxes need a full item vocabulary. Deferred to T-142 pending the user's call.
